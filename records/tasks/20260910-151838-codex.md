# 원형의 variant 배정을 프롬프트로 전달

- 워커: codex
- 발행: 2026-09-10 15:18:38
- 지휘: Claude Code (오케스트레이터 세션)

## 지시

## 문제 (실측)

카탈로그 25종에 블록별 variant 가 배정돼 있고 분포는 이렇다.

```
paper 57 · sand 39 · compact 35 · light 35 · full-bleed 16 · dark 16 · image-left 11 · image-right 11
```

그런데 **6차 재생성 실제 출력의 variant 분포는 이렇다.**

```
paper 22 · light 19 · image-left 4 · dark 3 · full-bleed 3 · image-right 2 · compact 1 · sand 0
```

카탈로그에서 두 번째로 많이 배정된 `sand` 가 **한 번도 나오지 않았다.**

원인을 확인했다. `src/detail_page_ai/prompts.py` 는 선택된 원형의 `sequence` 만 싣고
`variants` 는 전달하지 않는다. 그러면서 여전히 이렇게 지시한다.

> "Choose the remaining order, count, and **variants** from the product's visual character
> and available evidence."

즉 구성은 코드가 정하는데 variant 는 모델에게 맡기고 있어, 모델이 익숙한 `paper`/`light` 로
수렴한다. `web/detail_page.css` 에 네 종(`sand`·`image-left`·`image-right`·`compact`)의
규칙을 방금 구현했는데 `sand` 는 쓰이지 않는다.

## 작업

선택된 원형의 **블록별 variant 를 프롬프트에 함께 싣는다.**

- `src/detail_page_ai/layout_archetypes.py` 가 원형을 반환할 때 `variants` 도 함께 넘어가는지
  확인하라. 안 넘어가면 넘어가게 하라.
- `src/detail_page_ai/prompts.py` 가 구성 지시를 만들 때 각 블록의 variant 를 명시하라.
  형식은 네가 정하되 **블록과 variant 의 대응이 분명해야** 한다.
- **모순되는 지시를 제거하라.** "variants 를 제품 성격에서 고르라"는 문장이 남아 있으면
  코드가 지정한 값과 충돌한다. 구성을 코드가 정하기로 한 것과 같은 이유다.

**단, 근거 예외는 유지한다.** 지정된 블록을 뒷받침할 수 없으면 생략하는 규칙은 그대로 두어라.
variant 는 시각 처리라 사실성과 무관하므로 생략 대상이 아니다 — 블록이 남으면 지정 variant 를 쓴다.

## 확인

허용 variant 는 DTO 8종뿐이다: `paper`, `light`, `sand`, `dark`, `image-left`,
`image-right`, `full-bleed`, `compact`. 카탈로그가 그 밖의 값을 갖고 있으면 보고하라.

## 테스트

`tests/test_prompts.py` 에 추가:
1. 선택된 원형의 variant 가 프롬프트 문자열에 나타난다
2. "variants 를 골라라" 류의 상충 지시가 남아 있지 않다
3. 서로 다른 해시에서 **서로 다른 variant 조합**이 프롬프트에 실린다

`.venv/bin/python -m pytest -q` 전체 통과. 검사를 약화시키지 마라.

## 결과

### 변경 파일

- `src/detail_page_ai/prompts.py`
  - 선택된 원형의 `sequence`와 같은 위치의 `variants`를 `1. block_type → variant` 형식으로 프롬프트에 명시했습니다.
  - 각 출력 블록은 코드 지정 variant를 사용하고 모델이 variant를 선택·대체·재정렬하지 않도록 지시했습니다.
  - 근거 부족으로 블록을 생략할 때는 해당 블록의 variant도 함께 사라지고, 남은 블록은 원래 짝지어진 variant를 유지하도록 했습니다.
  - 허용 8종(`paper`, `light`, `sand`, `dark`, `image-left`, `image-right`, `full-bleed`, `compact`) 및 sequence/variant 길이를 검증해 유효하지 않은 원형은 선택 계약에서 제외합니다.
- `tests/test_prompts.py`
  - 동일 해시가 동일한 순번별 variant 배정을 프롬프트에 싣는지 검증했습니다.
  - 서로 다른 해시에서 최소 3개의 서로 다른 variant 조합이 실제 프롬프트에 나타나는지 검증했습니다.
  - 선택 프롬프트에 variant 선택 지시가 남지 않는지와 근거 기반 생략 예외의 유지 여부를 검증했습니다.

### 확인

- `select_layout_archetypes()`는 이미 카탈로그 entry 전체를 복사해 반환하므로 `variants`도 선택 결과에 전달됨을 확인했습니다. `layout_archetypes.py` 수정은 불필요했습니다.
- 카탈로그 25개를 검사한 결과, variant 값은 모두 허용 8종이고 각 `variants` 길이는 해당 `sequence` 길이와 일치했습니다. 보고할 잘못된 값은 없었습니다.
- 12개 해시의 선택 프롬프트에서 서로 다른 block+variant 배정 10개를 확인했습니다.
- `.venv/bin/python -m pytest -q tests/test_prompts.py` → `39 passed`.
- `.venv/bin/python -m pytest -q` → `298 passed in 3.67s`.
- 대상 변경 파일 `git diff --check` 통과.
