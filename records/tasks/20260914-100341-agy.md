## 관리자가 확인한 사실 (근거: HF API 파일 목록, SGLang 0.5.19 wheel 의 `sglang/multimodal_gen/runtime/server_args/server_args.py`)
- `black-forest-labs/FLUX.2-klein-9B` diffusers 구성: transformer 16.91 GiB, text_encoder 15.26 GiB, vae 0.16 GiB. 저장소 루트의 단일 파일 16.92 GiB 는 transformer 와 같은 가중치라 파이프라인 적재량에 더하지 않음. 게이트 저장소(`gated: auto`) → **`HF_TOKEN` 필수**(HF 에서 라이선스 동의 후 발급).
- `black-forest-labs/FLUX.2-klein-9b-fp8`: 단일 파일 `flux-2-klein-9b-fp8.safetensors` 8.79 GiB, 게이트. `nvfp4` 변형은 Blackwell 전용 FP4 라 L40S(Ada) 에서 쓰지 않음.
- g6e.xlarge: GPU 44.7 GiB, 시스템 RAM 32 GiB, 4 vCPU.
- 메모리 계산:
  - 9B 전부 GPU: 16.91+15.26+0.16=32.33 + 텍스트 AWQ 19.60 = 51.93 GiB → 가중치만으로 초과.
  - SGLang 기본값: 이미지 생성 작업은 `dit_cpu_offload`, `text_encoder_cpu_offload` 가 명시 안 하면 True(`_adjust_offload`), `pin_cpu_memory` 기본 True → 두 부품 32.2 GiB 를 호스트에 고정 → 32 GiB RAM 에서 OOM 위험.
  - **채택안:** transformer 를 FP8 가중치로 GPU 상주, text encoder 만 CPU. GPU = 텍스트 서버 할당 22.35(0.50) + 8.79 + 0.16 = 31.3 GiB, 여유 약 13.4 GiB(활성화·CUDA 컨텍스트 2개). RAM 에 text encoder 15.26 GiB, 고정하지 않음.
- SGLang 0.5.19 CLI 인자(소스 확인): `--text-encoder-cpu-offload`(StoreBoolean), `--dit-cpu-offload`, `--pin-cpu-memory`, `--performance-mode`, 그리고 동적 컴포넌트 가중치 경로 `--component-weights-paths.<component>` 의 별칭 `--<component>-weights-path` → `--transformer-weights-path`.

## 바꿀 것
1. `sglang-image` 기동 명령: `--model-path ${IMAGE_MODEL_PATH}`(기본 `black-forest-labs/FLUX.2-klein-9B`), `--transformer-weights-path ${IMAGE_TRANSFORMER_WEIGHTS_PATH}`, `--dit-cpu-offload false`, `--text-encoder-cpu-offload true`, `--pin-cpu-memory false`. 기존 `--pin-cpu-memory`(켜짐) 제거. `--performance-mode` 는 명시 인자와 충돌하지 않게 기본(auto)으로 두거나 빼세요.
   - `IMAGE_TRANSFORMER_WEIGHTS_PATH` 는 FP8 파일 경로입니다. SGLang 이 HF 저장소 파일을 직접 받는지 로컬 경로만 받는지 소스에서 확인되지 않았으므로, **확실한 방법으로**: 공유 HF 캐시 볼륨에 `huggingface-cli download black-forest-labs/FLUX.2-klein-9b-fp8 flux-2-klein-9b-fp8.safetensors` 로 받아 두고 그 로컬 경로를 넘기는 절차를 문서에 넣으세요. 로컬 경로 기본값을 `.env.example` 에 명시(예: `/root/.cache/huggingface/flux-2-klein-9b-fp8/flux-2-klein-9b-fp8.safetensors`)하고, compose 에 이 파일을 받는 1회성 준비 방법을 적으세요.
2. `.env.example`: `IMAGE_MODEL_PATH=black-forest-labs/FLUX.2-klein-9B`, `IMAGE_TRANSFORMER_WEIGHTS_PATH=...`, `HF_TOKEN` 주석을 "9B·FP8 는 게이트 저장소라 반드시 설정"으로. `IMAGE_SERVED_MODEL_NAME`/`LOCAL_IMAGE_MODEL` 이름 규칙은 유지.
3. `tests/test_security.py` 의 `IMAGE_MODEL_PATH` 기대값을 9B 로.
4. 문서 `ubuntu-deployment.md`:
   - 라이선스 절: 9B 는 FLUX Non-Commercial License 이며 **관리자 결정으로 채택**. 상업 운영 전 BFL 상업 라이선스 확인이 필요하다는 사실만 적고, 판단·권고는 쓰지 마세요.
   - 메모리 절: 위 세 방식 비교표와 채택안, RAM 32 GiB 에서 SGLang 기본 오프로드를 쓰면 안 되는 이유.
   - 첫 배포 체크리스트에 추가: FP8 트랜스포머 가중치가 L40S 에서 로드·생성되는지, 텍스트 인코더 CPU 오프로드 시 호스트 RAM 사용량(`free -g`)과 생성 지연, 편집(원본 참고) 품질. 실패 시 대안: RAM 64 GiB 인스턴스(g6e.2xlarge)에서 SGLang 기본 오프로드, 또는 이미지 모델 4B.
   - 모델 다운로드 크기 갱신.
5. `sglang-serving-research.md`: 결론 요약의 기본 이미지 모델을 관리자 결정(9B + FP8 트랜스포머 + 텍스트 인코더 CPU)으로 갱신하고, 4B 는 대안으로 남기세요. 라이선스 사실은 그대로.
