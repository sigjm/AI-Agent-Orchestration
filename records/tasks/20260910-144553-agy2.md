## 목표

공예 상세페이지가 **실제로 어떤 정보를 어떤 순서로 담는지** 실증 데이터를 모은다.
지금 카탈로그 25종은 관행과 판단으로 만든 것이라 근거가 약하다.

산출물은 `data/references/kcdf-structures.jsonl` 하나다 (디렉터리도 새로 만든다).

## 대상

한국공예디자인문화진흥원 온라인숍. 목록: `https://kcdfshop.kr/product/list2.html?cate_no=578`
총 996개, 50페이지. 상품 상세 URL 형태는 이렇다.

```
https://kcdfshop.kr/product/모란나비-옻칠나전-보석함/2422/category/578/display/1/
```

상세페이지는 긴 이미지 한 장이 아니라 **실제 텍스트 단락과 정보 테이블**로 되어 있음을
확인했다. 구조 추출이 가능하다.

## 반드시 지킬 경계 (이 항목이 가장 중요하다)

- **본문 카피와 이미지를 저장하지 마라.** 추출하는 것은 **구조**다.
  문단의 존재·순서·성격, 테이블의 항목명, 섹션 구분이지 그 내용이 아니다.
- 상품명은 **분류 목적으로만** 저장한다 (예: "보석함", "티매트"). 마케팅 문구는 저장 금지.
- 정보 테이블은 **항목명만** 모은다 (예: 소재, 규격, 구성, 용도). 값은 저장하지 마라.
- 이미지는 **개수와 위치만** 기록한다. 파일을 내려받지 마라.
- **요청 간격을 최소 1.5초 이상** 두어라. 동시 요청 금지.
- `robots.txt` 는 `/admin`, `/api`, `/member`, `/myshop`, `/protected`, 게시판 수정·작성,
  `page=`·`category_no=` 파라미터 URL을 차단한다. **그 경로는 건드리지 마라.**

프로젝트 규약이 "샘플 문구·상품명·정확한 화면을 복사하지 않는다"이고, 같은 선을 적용한다.

## 수집 범위

996개 전부는 과하다. **80~120개를 표본으로** 모아라. 목록 페이지를 앞에서부터 훑되,
품목이 한쪽으로 쏠리지 않게 여러 페이지에서 고르게 뽑아라.

## 항목별로 기록할 것

```json
{
  "product_id": "2422",
  "category_hint": "보석함",
  "sections": [
    {"kind": "intro_text", "paragraphs": 2, "has_image": false},
    {"kind": "image_block", "images": 4},
    {"kind": "spec_table", "fields": ["소재", "규격", "구성", "용도"]},
    {"kind": "notice", "paragraphs": 3}
  ],
  "section_count": 4,
  "total_images": 4,
  "has_spec_table": true,
  "spec_fields": ["소재", "규격", "구성", "용도"]
}
```

`kind` 는 네가 관찰한 대로 분류하되 **일관된 어휘를 쓰고, 어떤 기준으로 나눴는지 보고에
적어라.** 우리 13종 block_type 에 억지로 끼워 맞추지 마라 — 실제로 무엇이 있는지 보는 게
목적이다. 매핑은 다음 단계에서 다른 워커가 한다.

### 3. `kind` 어휘 및 분류 기준

지침에 따라 내부 13종 block_type에 억지로 끼워 맞추지 않고, KCDF 공예 상세페이지의 실제 DOM 구조와 의도에 기반하여 5종 어휘로 분류함:

1. `image_block`:
   - **분류 기준**: 상세페이지 상단(`cg-detail` 이전)에 연속으로 배치되는 시각적 이미지 요소들의 묶음.
   - **실제 구성**: 상세 비주얼 컷(제품 디테일 및 형태), 작가 소개 정보 컷, 작가 전용 페이지 이동 배너, 우수공예품 지정 배너 등.
   - **속성**: `images` (이미지 개수)
2. `intro_text`:
   - **분류 기준**: 이미지 블록 앞 또는 이미지 사이에서 독립적으로 제시되는 텍스트 문단.
   - **속성**: `paragraphs` (문단 수), `has_image` (이미지 동반 여부)
3. `notice`:
   - **분류 기준**: '구매 전 확인사항'(`info-box`) 섹션.
   - **실제 구성**: 수공예 특성(수작업 개체 차이, 기포, 색 배열 차이 등)과 소재별 취급/세척/보관 유의사항, 품질보증기준, A/S 및 고객센터 안내.
   - **속성**: `paragraphs` (문단 수)
4. `spec_table`:
   - **분류 기준**: '상품상세정보'(`table-wrapper`) 섹션의 제품 기술 사양 테이블.
   - **실제 구성**: 제품의 물리적 사양을 key-value 형식으로 제공하는 표준 테이블.
   - **속성**: `fields` (테이블에 포함된 항목명 배열; 값은 미저장)
5. `seller_info`:
   - **분류 기준**: 공시용 '판매자 정보'(`accordion`) 접이식 테이블.
   - **실제 구성**: 상호명, 사업자등록번호, 통신판매업번호, 대표자, 사업장 소재지 등 판매자 등록 정보.
   - **속성**: `fields` (테이블에 포함된 항목명 배열)
