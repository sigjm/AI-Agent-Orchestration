## 목표

BE/FE 통합 인터페이스 명세를 현재 코드와 대조해 갱신한다.

**새 문서를 만들지 마라.** 이미 `docs/api/be-fe-ai-integration-spec.md` 가 그 역할을 하고
있다. 새로 만들면 계약 문서가 둘로 갈라져 어느 쪽이 정본인지 알 수 없게 된다.
**수정 대상은 그 파일 하나다.**

추가로, 산출물 목록에서 찾아갈 수 있도록 `docs/deliverables/` 에서 이 문서를 가리키는
한 줄 링크가 필요하다. 그건 **`docs/deliverables/05-be-fe-interface.md` 라는 짧은 스텁**으로
만들어라 — 내용을 복제하지 말고, 정본이 `docs/api/be-fe-ai-integration-spec.md` 임을 밝히고
링크만 거는 5~10줄짜리 문서다. 계약 내용을 두 곳에 쓰지 마라.

## 대조할 코드 (직접 열어 확인할 것)

1. **엔드포인트** — `src/detail_page_ai/app.py`
   - 공개: `/api/v1/ai/detail-page-jobs`, `/api/v1/ai/detail-page-jobs/{job_id}`,
     `/api/v1/ai/detail-page-jobs/{job_id}/draft`, `/api/v1/ai/detail-page-renders`
   - 내부: 같은 경로의 `/internal/v1/ai/...` 계열, **`X-AI-Internal-Token` 헤더 필요**
   - 실제 메서드(GET/POST/PUT)와 경로를 코드에서 확인하고 문서와 다르면 문서를 고쳐라
2. **DTO** — `src/detail_page_ai/fe_dto.py`, `ai_dto.py`, `dto.py`
3. **구조 산출물 계약** — `src/detail_page_ai/react_document.py`
   `schemaVersion: "2.0"`, `canvasWidth`, `root[]`, 이미지 노드는 URL 대신 `props.imageId`
4. **작업 상태 전이** — 파이프라인이 내보내는 상태:
   `QUEUED → ANALYZING → EXTRACTING → GENERATING_BACKGROUNDS → COMPOSING → VERIFYING →
   RENDERING → DRAFT_READY → DELIVERING → COMPLETED`, 실패 시 `FAILED`.
   코드에서 실제 순서를 확인하라 (`src/detail_page_ai/pipeline.py` 의 `emit` 호출)
5. **설정 계약** — `AI_CORS_ORIGINS`, `AI_INTERNAL_AUTH_TOKEN`, `BACKEND_PRODUCT_URL`,
   `MAX_IMAGE_BYTES`, `MAX_SOURCE_IMAGES`, `MAX_REQUEST_BYTES`, `RESPONSE_ASSET_MODE`

1. **엔드포인트 대조 (`src/detail_page_ai/app.py`)**:

   - **로컬 직접 데모 API**: 10절에 `/api/v1/ai/detail-page-jobs`, `/api/v1/ai/detail-page-jobs/{job_id}`, `/api/v1/ai/detail-page-jobs/{job_id}/draft`, `/api/v1/ai/detail-page-renders` 4개 엔드포인트의 HTTP 메서드, 폼/JSON 파라미터, 반환 DTO(`AiFeJobAcceptedResponseDto`, `AiFeJobStatusResponseDto`, `AiFeDraftResponseDto`, `AiFeApprovedResponseDto`)와 `ENABLE_LEGACY_DEMO_API=true` 가드 조건 명시.

   - 3.1절에 FE가 소비하는 정식 구조 산출물이 `react_document`(`schemaVersion: "2.0"`, `canvasWidth: 774`, `root[]`)임을 명문화.
