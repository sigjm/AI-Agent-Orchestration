## 지시

## 설계는 확정됐다. 구현만 하라.

사양이 코드와 충돌하면 멈추고 보고하라. 임의로 설계를 바꾸지 마라.

## 배경 — 왜 이 방향인가

섹션 구성이 상품과 무관하게 고정되는 문제를 네 차례 고쳤고, 전부 "모델에게 말해서 바꾸기"였다.

1. `validation.py` 패딩 제거 → 변화 없음
2. 프롬프트 순서 각인 3곳 제거 → 최빈 5/6 → 3/6
3. 블록별 생략 조건(`statement` 게이트) → 고유 시퀀스 4종
4. 상품별 레이아웃 원형 4종 제시 → **오히려 악화** (평균 일치도 78.3% → 79.8%, 완전 일치 2쌍 → 3쌍)

조사 결과 **강제하는 코드는 어디에도 없다.** 렌더러는 `page_plan` 블록을 순서대로 돌고
(`_dynamic_sections`), 템플릿 이미지는 모델에 전달되지 않는다(`html_renderer.py` 에서 `del`).
즉 남은 원인은 모델의 기본값이고, 지시로 바꿀 여지는 소진했다.

그래서 **구성을 코드가 결정**한다.

## 구현 사양

### 1. 원형을 하나 고른다

`src/detail_page_ai/layout_archetypes.py` 에 이미 `select_layout_archetypes(image_sha256, user_hints, count)`
가 있다. 이것을 재사용해 **count=1** 로 원형 하나를 결정적으로 고른다.
같은 이미지 → 항상 같은 원형, 다른 이미지 → 다른 원형.

### 2. 프롬프트가 그 시퀀스를 명시적으로 지시한다

지금은 원형 넷을 "예시"로 보여준다. 이것을 **하나의 확정된 구성 지시**로 바꾼다.

- 선택된 원형의 `sequence` 를 그대로 싣고, **이 블록들을 이 순서로 만들라**고 지시한다
- `page_plan` 의 길이·구성을 모델이 정하지 않는다. 모델이 채우는 것은 **각 블록의 카피**다
- 기존의 "구성을 다양하게 하라", "고정 시퀀스를 쓰지 마라" 류의 지시는 **이제 모순이므로 제거**하라.
  코드가 구성을 정하는데 모델에게 다양화를 요구하면 충돌한다

### 3. 근거 규칙이 구조보다 우선한다 (이 항목이 가장 중요하다)

**구조 강제가 사실성 규칙을 이기게 만들지 마라.**

원형이 요구하는 블록을 이 제품에서 뒷받침할 수 없는 경우가 반드시 생긴다
(예: 크기 비교 자산이 없는데 `scale_reference`, 구성품이 하나인데 `component_inventory`).
그때 모델이 블록을 채우려고 내용을 지어내면, 이 프로젝트가 지켜온 것을 구조 다양성과
맞바꾸는 것이다.

따라서 프롬프트에 **좁은 예외**를 명시하라.

- 지정된 블록을 **이미지나 제공된 데이터로 뒷받침할 수 없으면 그 블록을 생략**한다
- 생략은 허용되지만 **없는 사실을 지어내 채우는 것은 금지**다
- 생략한 경우 남은 블록의 순서는 유지한다

기존 안전 문구(근거 없는 주장 금지, "확인 필요" 사용, 생성 컷 표기, care gate)는 전부 그대로 둔다.

### 4. 검증은 보고만 한다

`validation.py` 의 `ensure_editorial_page_plan` 은 **지금 동작을 유지**하라.
지정 시퀀스와 다르다고 해서 블록을 새로 만들어 채우지 마라. 그건 4차수 전에 제거한
패딩 동작이고, 지어낸 카피를 낳는다. hero 첫·closing 끝 정규화만 지금처럼 둔다.

### 5. 테스트

`tests/test_prompts.py` 에 추가한다.

1. 같은 해시는 항상 같은 원형 시퀀스를 프롬프트에 싣는다 (결정성)
2. 서로 다른 해시 여러 개에서 **적어도 세 개의 서로 다른 시퀀스**가 나온다
3. 프롬프트에 "구성을 다양하게 하라" 류의 상충 지시가 남아 있지 않다
4. 근거 없이 채우지 말고 생략하라는 예외 문구가 프롬프트에 있다
5. 카탈로그 파일이 없어도 예외 없이 동작한다 (원형 없으면 기존 방식으로 폴백)

`.venv/bin/python -m pytest -q` 전체(현재 293개) 통과. 검사를 약화시키지 마라.
