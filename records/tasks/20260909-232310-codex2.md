파일 경로와 심볼 이름을 함께 적어라.

## 다뤄야 할 것

### 1. 두 개의 API 층

이 서비스에는 성격이 다른 API 가 두 층 있다. 이 구분을 문서 앞에 명확히 세워라.

- **서비스 API** — `src/detail_page_ai/app.py` 의 FastAPI. 포트 8000.
  공개 `/api/v1/ai/...` 와 내부 `/internal/v1/ai/...`(`X-AI-Internal-Token` 필요)
- **모델 추론 API** — MLX Serve. 포트 11234. OpenAI 호환.
  서비스가 이쪽의 클라이언트가 된다

### 2. 모델 추론 클라이언트 (이 문서의 중심)

`src/local_detail_page_ai/clients.py` 를 읽고 정리하라.

- `MlxServeChatClient` — 텍스트·비전 분석. 어느 엔드포인트를 쓰는지, JSON 스키마 강제를
  어떻게 거는지, 타임아웃·최대 토큰 기본값
- `MlxServeImageClient` — 이미지 생성·편집. **generate 와 edit 두 경로가 서로 다른
  엔드포인트를 쓴다.** 왜 그렇게 됐는지가 중요하다:
  multipart `/v1/images/edits` 는 MLX Core 26.9.1 에서 내부적으로 `mode:"edit"` JSON 으로
  변환되며 `steps`·`strength` 를 전달하지 않는다. 그래서 edit 을 JSON `mode:"edit"` 경로로
  전환했고, 참조 이미지를 base64 로 싣는다. 이 경위를 문서에 남겨야 다음 사람이 되돌리지 않는다
- `OllamaChatClient` — 대체 provider. 운영 기본 경로가 아니라는 점을 명시
- transport 추상화(`JsonTransport` 등)와 그것이 테스트에서 어떻게 스텁되는지

### 3. 설정 계약

`src/detail_page_ai/config.py` 와 `.env.example` 을 대조해 정리하라.
추론과 관련된 것만 추려라: `ANALYSIS_PROVIDER`, `LOCAL_TEXT_PROVIDER`, `LOCAL_TEXT_URL`,
`LOCAL_TEXT_MODEL`, `LOCAL_TEXT_TIMEOUT`, `LOCAL_IMAGE_*`, `BACKGROUND_PROVIDER`,
`PROMPT_VERSION`. 각각의 기본값과 의미를 표로.

현재 모델은 텍스트 `ddalcu/Qwen3.8-27B-MLX-Serve-4bit`, 이미지 `mlx-community/flux2-klein-9b-4bit` 다.

### 4. 어댑터와 파이프라인 연결

`src/local_detail_page_ai/adapters.py` 와 `runner.py` 가 위 클라이언트를 파이프라인 포트
(`src/detail_page_ai/ports.py`)에 어떻게 꽂는지 정리하라. **이 경계가 CUDA 이관 시 교체
지점**이라는 점을 명시하라 — 클라이언트가 OpenAI 호환 계약만 지키면 상위 코드는 바뀌지 않는다.

### 5. 요청·응답 예시

각 엔드포인트에 대해 실제 페이로드 모양을 코드에서 뽑아 예시로 넣어라.
**응답 본문을 지어내지 마라.** 실제 값을 확인할 수 없으면 필드 구조만 적고 그렇다고 표시하라.

## 반드시 지킬 것

  git commit / push 금지.

### 미해결 이슈

- 모델 client의 실제 응답 본문과 base64 값은 호출하지 않았으므로 문서에는 코드상 응답 필드 구조만 기록했다.
- `PROMPT_VERSION`은 `config.py` 기본값 `local-mlx-qwen-flux-v1`과 `.env.example` 명시값 `detail-page-source-safe-v2`가 다르며, 문서에 환경변수 override 관계를 명시했다.
- `clients.py`의 `steps=4` 소스 반영은 다른 워커 작업 범위이며, 이 작업에서는 문서만 갱신했다.
