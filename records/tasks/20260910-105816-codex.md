**교차검증이다.** 다른 워커 한 명이 지금 **같은 브리프로 독립 작업 중**이다.

- 상대의 결과 파일이나 `.orchestration/tasks/` 의 다른 브리프를 **열어보지 마라**
- 상대와 같은 결론을 내려고 맞추지 마라. 네가 근거로 도달한 결론을 써라
- 확신이 없으면 없다고 써라. 억지로 단정하는 것보다 낫다

## 증상 (실측)

상품 종류가 달라도 상세페이지의 섹션 시퀀스가 거의 동일하다.

**수정 전** (`generated/evaluation/pilot-20260909-224737`):

recommendation, info_table, notice, closing. jewelry 만 9블록(statement 없음).

**수정 후** (`generated/evaluation/pilot-20260910-102346`):

## 이미 배제된 원인

`src/detail_page_ai/validation.py` 의 `ensure_editorial_page_plan()` 이 모델 계획에 없는
블록을 채워 넣던 동작은 **이번에 제거했다.** 중간 블록이 6개 이상이면 모델의 블록 종류와
순서를 그대로 보존한다. 그런데도 위와 같이 여전히 고정이다.

즉 **코드가 손을 뗀 뒤에도 모델이 같은 시퀀스를 낸다.** 원인은 모델 입력 쪽에 있다.

## 조사할 것

`src/detail_page_ai/prompts.py` 의 `build_analysis_prompt()` 를 읽어라.
이 프롬프트는 이미 다음을 명시하고 있는데도 지켜지지 않는다:

> The layout choice is only a backward-compatible style hint, not the page layout.
> The authoritative layout is page_plan. **Do not use one fixed sequence for every product.**

금지 문구가 있는데 왜 안 지켜지는지가 이 작업의 질문이다. 프롬프트의 구조·어순·예시·
스키마 설명 중 무엇이 모델을 한 시퀀스로 몰고 있는지 찾아라. 실제 산출물
(`result_summary.json` 의 `page_plan`)과 프롬프트를 대조하면 단서가 보인다.

## 산출물

`.orchestration/proposals/prompt-fixed-sequence-codex.md` **하나만** 만든다. 다음을 담아라.

1. **진단** — 프롬프트의 어느 부분이 원인이라고 보는가. 해당 문장을 **원문 인용**하고,
   그것이 산출물의 어떤 패턴으로 나타나는지 연결하라. 추측이면 추측이라고 표시하라.
2. **개정안** — 구체적인 수정안. 바꿀 문장을 before/after 로 제시하라.
   프롬프트 전체를 다시 쓰지 말고 **최소 변경**으로 제안하라.
3. **검증 가능한 예측** — 이 개정이 통하면 산출물에서 **무엇이 어떻게 달라져야 하는가**를
   미리 적어라. "좋아진다" 같은 말 말고, 다음 재생성에서 확인할 수 있는 형태로.
   (예: 카테고리 6건 중 최소 N건의 블록 집합이 달라진다)
4. **위험** — 이 개정이 깨뜨릴 수 있는 것. 특히 `page_plan` 은 DTO 검증을 통과해야 하고
   최대 14블록 제한이 있다.

## 결과

### 변경 파일

- `.orchestration/proposals/prompt-fixed-sequence-codex.md`를 만들었다. 두 파일럿의 `page_plan` 분포와 프롬프트·참조 가이드의 문장을 대조해 원인을 진단하고, `prompts.py`에 적용할 최소 before/after 개정안·재생성 판정 기준·위험을 제안했다.
- 이 작업 파일에는 결과 보고만 추가했다. `src/`, `tests/`, `scripts/`, `docs/`, `generated/` 및 `prompts.py`는 수정하지 않았다.

### 검증 방법과 근거

- 두 파일럿의 `result_summary.json`에서 `product.page_plan`의 block_type을 읽어, 수정 전 최빈 10블록 시퀀스가 5/6, 수정 후 recommendation만 빠진 9블록 시퀀스가 5/6임을 재집계했다. 수정 후의 다섯 계획은 중간 블록 7개이고 jewelry는 6개이므로, 현재 `ensure_editorial_page_plan()`의 보존 분기(중간 블록 6개 이상)에 따라 삽입된 결과가 아니다.
- `build_analysis_prompt()`의 고정 금지 문장과 그 뒤의 `Open`/`Follow`/`Include`/`Finish` 순서형 규칙, 9~12 최소치, 무조건적인 feature-card 문장을 확인했다. 주입된 reference guide의 `hook → proof → context → use → information → close` 및 종결 문구도 확인했다.
- 제안 문서는 진단, 최소 개정안, 검증 가능한 예측, 위험 섹션을 모두 포함하는지와 Markdown 공백 오류가 없는지를 별도 점검해 통과했다.

### 미해결 이슈

- 이 문서는 교차검증용 제안이므로 프롬프트 변경이나 모델 재생성은 수행하지 않았다. 오케스트레이터가 독립 제안과 대조해 채택안을 결정해야 한다.
- 채택 뒤에는 동일 6개 입력·동일 모델 조건으로 재생성해 제안서의 `최소 3개 전체 시퀀스`, `최빈 시퀀스 최대 2/6`, DTO·gallery·care-notice 계약 보존 예측을 검증해야 한다.
- 실제 적용 시 현재 프롬프트 문자열을 전제하는 `tests/test_prompts.py` assertion도 새 계약에 맞춰 갱신이 필요하다.
