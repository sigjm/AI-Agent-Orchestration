배경:
- src/detail_page_ai/prompts.py 의 _format_selected_layout_instruction 에는 분기가 두 개 있다.
  - 후보가 여러 개면 "choose exactly one" (모델이 고름) — 지금 어댑터가 쓰는 경로(count=4)
  - 후보가 정확히 1개면 "Code-selected layout plan:" (코드가 확정) — 현재 아무도 안 쓰는 경로
- 직전 실행에서 모델은 제시된 4종 원형 중 어느 것과도 일치하지 않는 시퀀스를 만들었다.
  제시: material-color-scale / component-assembly / color-system-led / silhouette-proof
  모델 출력: hero, statement, palette, wide_image, feature_grid, recommendation, notice, closing
  (gallery 조차 없었다. 골격 규칙도 안 지켰다.)

할 일:
1. 스크래치패드에 단독 측정 스크립트를 만든다. 프로젝트 소스는 한 줄도 고치지 마라.
2. detail_page_ai.layout_archetypes.LAYOUT_ARCHETYPES 에서 sequence 에 usage_scene 이
   들어있는 원형 3종을 고른다.
3. 각 원형에 대해 build_analysis_prompt(..., archetypes=[그 원형 하나],
   image_generation_enabled=True) 로 프롬프트를 만들고, 부채 이미지로 모델을 호출한다.
   - 이미지: <scratchpad>/fan/fan.jpg
   - 모델: MLX Serve http://127.0.0.1:11234 · ddalcu/Qwen3.8-27B-MLX-Serve-4bit (이미 떠 있음)
   - 호출은 손으로 HTTP 짜지 말고 src/local_detail_page_ai 의 기존 클라이언트를 재사용하라.
   - user_hints 는 부채 세트에 맞게(제품명/제작과정/관리법) 넣어라. making_method 가 있어야
     statement 계열 원형이 후보에 남는다.
4. 각 실행마다 다음을 표로 보고하라:
   - 코드가 지정한 시퀀스
   - 모델이 낸 page_plan 블록 순서
   - 완전 일치 여부 (True/False)
   - usage_scene 포함 여부 (True/False)
   - 일치하지 않았다면 무엇이 빠지고 무엇이 추가됐는지

보고: 위 표 + 한 문장 결론("코드 확정 분기로 모델이 따른다/안 따른다"). 추측 말고 실측만.
