## 지시

## 문제

카탈로그(`assets/references/detail-page-layouts.json`) 25종 **자체의 다양성이 상한**이다.
시뮬레이션으로 확인했다. 25종에서 6종을 중복 없이 뽑아도 평균 집합 일치도가 **63.9%** 다.
파이프라인을 아무리 고쳐도 이보다 다양해질 수 없다.

원인은 몇몇 블록이 거의 모든 원형에 들어 있기 때문이다.

```
closing 25/25 · hero 25/25 · notice 24/25 · info_table 24/25 · detail_split 22/25 · usage_scene 21/25
```

`hero` 와 `closing` 은 DTO 가 첫·마지막으로 강제하니 어쩔 수 없다. 문제는 나머지 넷이다.
**`notice`·`info_table`·`detail_split`·`usage_scene` 이 사실상 모든 원형에 붙어 있어,
어떤 조합을 뽑아도 6종 중 4종이 겹친다.**

## 작업

카탈로그의 다양성을 실제로 올린다. 기존 25종을 다 버리지 말고 **붙박이를 걷어내는 방향**으로 손본다.

### 1. 붙박이 완화

`notice`·`info_table`·`detail_split`·`usage_scene` 각각이 **25종 중 60~70% 정도에만**
등장하도록 조정하라. 지금은 84~96%다.

**아무 원형에서나 빼지 마라.** 각 원형의 `when`·`rationale` 을 읽고, **그 원형의 성격상
그 블록이 꼭 필요하지 않은 것**에서 빼라. 예를 들어 크기 비교가 핵심인 원형에
`usage_scene` 이 반드시 있어야 할 이유는 없다.

블록을 빼면 `middle_count` 와 길이가 바뀐다. **중간 블록이 6개 미만이 되면 안 된다** —
`validation.py` 가 그 아래에서 누락 블록을 채워 넣어 원점으로 돌아간다. 빼는 만큼 그 원형에
어울리는 다른 블록으로 채우거나, 애초에 길이가 넉넉한 원형에서만 빼라.

### 2. 덜 쓰이는 블록을 늘려라

13종 중 어떤 블록이 카탈로그에서 몇 번 쓰이는지 세어 보고, **적게 쓰이는 것들의 등장을 늘려라.**
`scale_reference`·`palette`·`wide_image`·`recommendation`·`statement` 쪽이 그럴 것이다.
다만 각 원형의 `when` 과 어긋나게 억지로 넣지 마라.

### 3. 목표 수치

작업 후 **직접 시뮬레이션을 돌려 확인하라.** 아래 코드를 참고하되 스크립트 파일로 남기지는 마라
(다른 워커가 `scripts/` 에서 작업 중이다). 임시로 실행해 수치만 확인하면 된다.

```python
import json, itertools, random, statistics
from pathlib import Path
c = json.loads(Path('assets/references/detail-page-layouts.json').read_text(encoding='utf-8'))
items = c['layouts'] if isinstance(c, dict) and 'layouts' in c else c
sets = [set(i['sequence']) for i in items]
rng = random.Random(0)
def mj(idxs):
    return statistics.mean(len(sets[a]&sets[b])/len(sets[a]|sets[b]) for a,b in itertools.combinations(idxs,2))
print(statistics.mean(mj(rng.sample(range(len(items)),6)) for _ in range(3000)))
```

**목표: 중복 없이 6종 추출 시 평균 집합 일치도 55% 이하.** 현재 63.9% 다.
달성하지 못하면 **얼마까지 내렸는지 그대로 보고하라.** 수치를 맞추려고 원형의 `when` 과
어긋나는 조합을 만들지 마라 — 그러면 카탈로그가 거짓말을 하게 된다.
