## 문제
`uv run pytest` 로 돌리면 테스트 2개 파일이 **수집 단계에서 실패**한다.

```
ERROR tests/test_attached_detail_page.py — ModuleNotFoundError: No module named 'scripts'
ERROR tests/test_eval_runner_cli.py     — ModuleNotFoundError: No module named 'scripts'
```

- `tests/test_attached_detail_page.py:1` 은 `from scripts.runtime.demo_fixed_profile_render import build_profile` 를,
  `tests/test_eval_runner_cli.py:8` 은 `from scripts import run_eval_pilot` 를 import 한다.
- `pyproject.toml` 의 `[tool.pytest.ini_options]` 에 `pythonpath = ["src"]` 만 있어 **저장소 루트가 sys.path 에 없다.**
- README.md:246 이 안내하는 `.venv/bin/python -m pytest -q` 는 cwd 가 sys.path 에 들어가서 우연히 통과한다(358 passed). 즉 호출 방식에 따라 결과가 갈린다.

## 고칠 것
`pythonpath` 에 저장소 루트를 추가해 **두 호출 방식이 모두 358 passed** 가 되게 할 것.

- `scripts/` 에 `__init__.py` 를 만드는 방식은 쓰지 말 것. 저장소의 스크립트는 패키지가 아니라 실행 스크립트다.
- `conftest.py` 를 새로 만들지 말 것. 설정 한 줄로 끝나는 문제다.
- 테스트 파일이나 import 문은 고치지 말 것.

## 검증 (둘 다 반드시 실행하고 결과를 적을 것)
1. `uv run pytest -q` → **358 passed**, 수집 에러 0
2. `.venv/bin/python -m pytest -q` → **358 passed**

## 결과

### 변경 파일

- pyproject.toml:25 · `pythonpath = ["src"]` → `pythonpath = [".", "src"]`

### 검증 방법

- `UV_CACHE_DIR=/private/tmp/team3-uv-cache uv run pytest -q` 실행 결과 마지막 줄: `358 passed, 2 warnings in 10.57s`
- `.venv/bin/python -m pytest -q` 실행 결과 마지막 줄: `358 passed, 2 warnings in 10.73s`
- 처음 실행한 `uv run pytest -q`는 기본 uv 캐시 경로 권한 오류로 시작하지 못했으며, 저장 가능한 임시 캐시 경로를 지정한 동일 pytest 실행으로 검증을 완료했다.

### 미해결 이슈

- 테스트 수집 오류는 해결되었다. 기본 `~/.cache/uv` 캐시 권한은 실행 환경 제약이므로, 해당 환경에서는 `UV_CACHE_DIR` 지정이 필요하다.
