## 배경

앞선 재생성 작업은 네 샌드박스가 `127.0.0.1:11234` 접근을 막아서(curl exit 7) 진행할 수
없었다. 판단은 정확했다 — 서버를 임의로 띄우지 않고 중단하고 보고한 것이 맞다. 그 작업은
네트워크가 열린 다른 워커에게 넘겼다. 이번 작업은 네트워크가 필요 없다.

## 목표

아키텍처·산출물 문서를 현재 코드에 맞게 최신화한다. 수정 대상은 다음 **두 파일뿐**이다.

- `docs/architecture/ai-architecture-design.md`
- `docs/deliverables-audit.md`

## 반영해야 할 변경 (모두 커밋된 사실이다)

1. **텍스트 모델 교체**: `mlx-community/gemma-4-12b-it-4bit` -> `ddalcu/Qwen3.8-27B-MLX-Serve-4bit`.
   이미지 모델 `mlx-community/flux2-klein-9b-4bit` 는 그대로. `PROMPT_VERSION` 은
   `local-mlx-qwen-flux-v1`. 두 문서에서 `grep -n -i "gemma"` 로 남은 표기를 전부 찾아 고쳐라.

2. **컷아웃 마스크 알고리즘 변경**: 배경을 이미지 테두리에서 4-이웃 flood fill 로 연결된
   영역으로만 정의한다. 밝은 제품이 밝은 배경 위에 있어도 제품 내부가 보존된다.
   마스크가 파편화되면 `extract` 가 `None` 을 반환하고 파이프라인이 원본으로 fallback 한다.
   근거는 `src/detail_page_ai/source_photos.py` 를 직접 읽어라. 문서에 알파 마스크 추출을
   설명한 부분이 있으면 이 동작으로 고쳐라.

3. **장신구 씬 분기 추가**: `_product_scene_direction` 에 장신구 전용 분기가 생겼다
   (`src/detail_page_ai/prompts.py`). 문서가 제품 유형별 씬 방향을 다루면 반영하라.

4. **`docs/deliverables-audit.md` 의 평가 항목**: 평가가 실제로 1회 실행됐다.
   파일럿 6건이 전건 성공했고 자동 gate(React schema validity, tree safety, alias
   serialization, imageId 해석 48/48, 원본 SHA-256 일치, executable field 누출 0건)를
   모두 통과했다. 다만 그 gate 를 전부 통과한 상태에서 컷아웃이 제품을 지운 사례가 2건
   있었고, 그래서 `scripts/check_cutout_fidelity.py` 와
   `scripts/check_scene_direction_coverage.py` 두 게이트가 추가됐다.
   자세한 기록은 `docs/evaluation/pilot-report-2026-09-09.md` 에 있으니 링크로 연결하라.
   **60건 전체 평가와 사람 검수는 아직 실행되지 않았다.** 이 점을 흐리지 마라.

## 반드시 지킬 것

- **사실만 적어라.** 측정되지 않은 수치나 존재하지 않는 검수 점수를 지어내지 마라.
  기존 문서가 "구현 충족(연동 대기)" 같은 판정을 쓰고 있으면 그 판정 체계를 그대로 따르고,
  근거 없이 판정을 올리지 마라.
- 기존 문서 구성을 유지하라. 통째로 다시 쓰지 말고 필요한 곳만 고친다.
- **위 두 파일 외에는 어떤 파일도 수정하지 마라.** `src/`, `tests/`, `scripts/`,
  `README.md`, `docs/README.md`, `docs/architecture/runtime-architecture.html`,
  `docs/architecture/ai-architecture-and-safety.md`, `docs/evaluation/**` 는 읽기 전용이다.
  다른 워커 셋이 `scripts/`, `README.md`, `generated/` 를 각각 작업 중이다.
- 모델 서버(11234) 끄기 금지 (다른 워커가 재생성 실행 중), 파일럿 실행 금지,
  git commit / push 금지.
