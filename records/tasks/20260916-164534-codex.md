### 2. 주요 변경 내역 및 근거

1. **추론 서버 규격 교체 (`sglang-final-facts.md` 정본 1:1 반영)**:
   - 기존의 레거시 서술인 `nvidia/cuda:12.4.1-runtime-ubuntu22.04` + vLLM + "Diffusers + MLX JSON 프록시"를 전면 폐기하고, 확정된 SGLang 2프로세스 규격으로 교체했습니다.
   - **텍스트·비전 서버 (`sglang-text`)**: 이미지 `lmsysorg/sglang:v0.5.19`, 모델 `cyankiwi/Qwen3.8-27B-AWQ-INT4` (가중치 19.60 GiB, 고정 커밋 `6e134bae811fb5adac50ee042ae5f029ac6779aa`), 포트 30000, 공개명 `qwen-text`, 기동 옵션 `--mem-fraction-static 0.50 --context-length 8192 --trust-remote-code`, 헬스체크 `GET /v1/models`.
   - **이미지 확산 서버 (`sglang-image`)**: 이미지 `local/sglang-diffusion:0.5.19` (`docker/sglang-diffusion.Dockerfile` 기반, `sglang[diffusion]==0.5.19` 및 `bitsandbytes==0.50.2` 설치), 모델 `circulus/FLUX.2-klein-9B-bnb-4bit` (약 10.2 GiB, 고정 커밋 `58c2804f31af12c8888504b96250010c50b55e44`), 포트 30001, 공개명 `flux-klein`, 기동 옵션 `--dit-cpu-offload false --text-encoder-cpu-offload false`, 헬스체크 `GET /v1/models` (확산 서버에는 `/health` 없음 명시).

2. **갭 4가지 재작성 (해소 상태 및 근거 갱신)**:
   - **갭 1 (MLX 종속성)**: **[해소됨]** Linux CUDA 호환 SGLang 2프로세스 서빙 스택 채택으로 해소.
   - **갭 2 (가중치 포맷 불일치)**: **[해소됨]** Qwen AWQ INT4 및 FLUX.2 bnb-4bit 채택과 허브 커밋 영구 고정, 볼륨 `huggingface-cache` 1회 캐싱으로 해소. FLUX Non-Commercial 라이선스 조건 사실 명시.
   - **갭 3 (이미지 편집 호출 규약 불일치)**: **[해소됨]** `src/local_detail_page_ai/clients.py`에 `sglang` provider를 구현하여 생성 시 JSON `POST /v1/images/generations`(`num_inference_steps` 등), 편집 시 multipart `POST /v1/images/edits`(`image` 필드)로 SGLang 네이티브 호출을 분리 지원하므로 Diffusers 앞단의 별도 프록시 어댑터 불필요.
   - **갭 4 (정적 자산 누락)**: **[해소됨]** `Dockerfile`에 `COPY assets/references/detail-page-layouts.json` 레이어가 추가되어 20종 레이아웃 카탈로그 정상 탑재 확인.

3. **EKS 현황 사실 반영 및 운영 경로 분리**:
   - 현재 확정된 운영 경로는 **단일 AWS EC2 `g6e.xlarge` (NVIDIA L40S 48GB 1장, Ubuntu) + `docker compose` (3개 서비스 단일 호스트 공존)**임을 문서 전면에 명시했습니다.
   - 현재 저장소에는 EKS 매니페스트(Deployment/Service/PVC), Helm 차트가 전무한 **미결정 상태**임을 기록했습니다.
