## 지시

## 목표

평가 데이터셋에서 카테고리당 1건씩 총 6건을 뽑아 로컬 파이프라인으로 실제 생성하고,
산출물과 실행 기록을 남기는 스크립트 `scripts/run_eval_pilot.py` 를 새로 만든다.

## 입력 데이터 (이미 존재한다. 새로 만들지 마라)

- `data/evaluation/cma_real_v1/manifest.json` — `assets` 배열의 각 항목에 `asset_id`,
  `category`(textile/box/metalware/ceramic/jewelry/furniture 각 10건), `image_path`, `sha256` 가 있다.
- `data/evaluation/cma_real_v1/analysis_60.jsonl` — case 별 `case_id`, `asset_id`,
  `metadata`(product_id, idempotency_key, locale, user_hints, options), `checks`.

## 선정 규칙

- 6개 카테고리에서 각 1건. **결정적으로** 고른다: 같은 카테고리 안에서 `asset_id` 오름차순
  정렬 후 첫 번째. 무작위 선택 금지 (다시 돌렸을 때 같은 6건이 나와야 한다).
- 선정 결과는 `--dry-run` 으로 모델 호출 없이 먼저 출력할 수 있어야 한다.

## 실행

- 실행은 `scripts/run_local_detail_page.py` 가 쓰는 것과 같은 경로를 사용한다:
  `src/local_detail_page_ai/runner.py` 의 `build_local_pipeline(...)` 과 `save_pipeline_result(...)`.
  그 스크립트를 읽고 인자 구성을 그대로 따르되, 여러 건을 순차로 돌리도록 감싼다.
- 모델 기본값은 건드리지 말고 현재 기본값을 그대로 쓴다
  (텍스트 `ddalcu/Qwen3.8-27B-MLX-Serve-4bit`, 이미지 `mlx-community/flux2-klein-9b-4bit`,
  둘 다 `http://127.0.0.1:11234`). CLI 플래그로 덮어쓸 수 있게만 해 둔다.
- 출력 위치: `generated/evaluation/pilot-<YYYYMMDD-HHMMSS>/<case_id>/`
- 실행 요약 `generated/evaluation/pilot-<...>/run_index.json` 에 건별로 기록한다:
  case_id, asset_id, category, 입력 이미지 경로와 sha256, 텍스트/이미지 모델 ID,
  시작·종료 시각, 소요 초, 성공 여부, 실패 시 예외 메시지와 트레이스 요약, 산출물 경로.

## 반드시 지킬 것

- **한 건이 실패해도 중단하지 말고 다음 건을 계속 실행**하고, 실패를 기록에 남긴다.
  실패 건을 결과에서 조용히 빼지 마라. 평가에서 실패율은 그 자체가 지표다.
- 모델 서버가 안 떠 있을 수 있다. 연결 실패도 위와 같이 기록하고 계속 진행한다.
- 기존 파일 수정 금지. **새 파일 `scripts/run_eval_pilot.py` 하나만 추가**한다.
  `src/`, `tests/`, `docs/`, `data/` 는 읽기만 한다. 데이터셋 파일은 절대 수정하지 마라.
- git commit / push 금지. 모델 서버를 직접 띄우지 마라 (지휘자가 별도로 처리한다).
- 검증은 `--dry-run` 실행으로 6건 선정이 맞게 나오는지까지만 한다. 실제 생성은 돌리지 마라.
