## 배경

너와 agy 가 독립으로 진단한 결과를 오케스트레이터가 대조하고 원문으로 검증했다.
**두 진단이 각각 상대가 놓친 원인을 하나씩 찾았고, 셋 다 사실로 확인됐다.**
네 제안서는 `.orchestration/proposals/prompt-fixed-sequence-codex.md` 에 있다.
**agy 의 제안서(`-agy.md`)도 이제 읽어도 된다** — 대조가 끝났으므로 독립성 제약은 해제한다.

확인된 원인은 셋이고, `src/detail_page_ai/prompts.py` 가 같은 순서를 **세 번** 각인한다.

1. **61행 Copy Map** (agy 발견) — "Use this section-aware copy map when composing page_plan:"
   뒤에 hero → statement → feature_grid → detail_split → usage_scene … 순으로 블록 설명이 나열된다.
   관측 시퀀스와 같은 순서다.
2. **141행 하한** (둘 다 발견) — "page_plan must contain 9 to 12 safe, whitelisted blocks."
   필수로 읽히는 블록이 hero, detail_split, usage_scene, gallery, recommendation, info_table,
   notice, closing 8개뿐이라 9 하한이 최소 1개 추가를 강제한다.
3. **160~180행 구성 규칙** (둘 다 발견) — "Open with … / Follow with … / Include … /
   Finish with …" 순차 명령 9개. 이 불릿 순서가 관측 시퀀스와 1:1 일치한다.

금지 문구 "Do not use one fixed sequence for every product." 는 139행과 180행,
**두 순서 목록 사이에** 있다. 구체적 명령 사이에 낀 추상적 부정문은 작동하지 않았다.

## 적용할 것

네 제안서의 A·B·C 와 agy 제안서의 2.1·2.2·2.3 을 합쳐 **최소 변경**으로 적용하라.
두 안이 겹치는 부분은 하나로 합치고, 어긋나면 네가 판단하되 **판단 근거를 결과 보고에 적어라.**

핵심 방향은 셋이다.

- **Copy Map 의 순서 신호를 없앤다.** 블록별 설명은 유지하되, 그것이 **순서가 아니라 참조표**임이
  드러나게 하라. 나열 순서 자체가 신호가 되지 않도록 하는 것이 목적이다.
- **구성 규칙을 순차 레시피에서 제약으로 바꾼다.** "무엇이 필수이고 무엇이 선택인가"와
  "hero 가 처음, closing 이 마지막"만 규칙으로 남기고, 중간 순서는 근거가 정하게 하라.
  imperative 나열 순서가 곧 출력 순서가 되는 구조를 없애는 것이 핵심이다.
- **하한을 실제 필수 집합과 맞춘다.** 9 하한이 억지 블록을 만들고 있다. `validation.py` 가
  중간 블록 6개 이상에서 모델 계획을 보존하므로 그 경계와 어긋나지 않게 정하라.

## 합격 기준 (다음 재생성으로 판정한다)

너와 agy 가 독립적으로 같은 기준을 냈다. 그것을 그대로 쓴다.

1. 6건에서 **최소 3개의 서로 다른 전체 block_type 시퀀스**가 나오고,
   **단일 시퀀스 빈도가 최대 2/6** 이다. (현재 5/6)
2. 모든 계획이 hero 첫 번째, closing 마지막, 허용 block_type 만 사용하고
   `ProductProfileDto` 의 최대 14블록 제한을 통과한다.
3. gallery 가 포함된 계획은 기존 photo_ids 5개 계약을 유지한다.
4. care_guide 가 없는 입력의 notice 문구가 기존과 동일하게 유지된다.

3·4 는 구조 다양화가 안전성·이미지 계약을 훼손하지 않는지 보는 관찰값이다.

## 결과

### 변경 파일

- `src/detail_page_ai/prompts.py`
  - Copy Map을 `Section copy reference`로 명시하고 block_type 이름순으로 정렬해, 설명은 보존하면서 목록을 page-plan 순서로 읽지 않게 했다.
  - `page_plan` 하한을 9에서 8로 낮추고, 최소 개수를 채우기 위한 일반 블록 추가를 금지했다. hero·closing과 중간 블록 6개의 현재 validation 보존 경계에 맞춘 값이다.
  - `Open`/`Follow`/`Include`/`Finish` 레시피를 제거하고, hero-first·closing-last·gallery·care notice의 필수 골격, 증거 기반 선택 메뉴, 조건별 선택 기준, 비필수 아키타입 선호도로 바꿨다. gallery의 5개 `photo_ids`와 care notice 문구의 기존 data gate는 유지했다.
  - feature-grid의 세 카드 조건을 `feature_grid` 선택 시에만 적용하도록 조건화했다.
- `tests/test_prompts.py`
  - 새 프롬프트 계약(8~12, 비순차 Copy Map, 필수 골격, 메뉴형 선택, 기존 레시피 제거, gallery photo_ids)을 검증하도록 기존 테스트를 갱신했다. 공백 정규화는 f-string 줄바꿈이 아닌 실제 계약을 검증하기 위한 것이다.

### 제안안 병합 판단

- agy의 Copy Map 참조표화와 8블록 하한은 채택했다. 목록을 단지 비순차라고 선언하는 것보다, 실제 나열도 알파벳순으로 바꿔 관측된 출력 순서와의 반복 신호를 제거했다.
- agy의 아키타입별 고정 시퀀스는 채택하지 않았다. 그것은 이번 브리프의 “중간 순서는 근거가 정한다” 및 “순차 레시피 제거”와 충돌해, 다른 형태의 고정 시퀀스를 다시 만들기 때문이다. 대신 archetype을 블록 선택의 선호도로만 사용했다.
