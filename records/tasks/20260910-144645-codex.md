## 대조 결과

너와 agy 의 CSS 안을 오케스트레이터가 대조했다. **네 안을 기반으로 채택한다.**
`web/variants-agy.css` 를 이제 읽어도 된다 (독립성 제약 해제).

**네 안이 나은 지점**

1. **색을 기존 토큰에서 파생시켰다** — `color-mix(in srgb, var(--yellow-500) 18%, var(--jade-blue-50))`.
   agy 는 `#EAE1D6` 이라는 새 색을 하드코딩했다. 이 프로젝트는 디자인 가이드를
   `reference_guide.py` 에 버전 고정하는데, CSS 가 별도 색을 가지면 그 고정이 무너진다.
2. **agy 는 존재하지 않는 토큰을 썼다** — `var(--ink)`. `detail_page.css` 의 토큰은
   `--black`·`--cool-grey-*` 계열이다. 색이 적용되지 않는다.
3. 네 안은 `.detail-page--adaptive` 스코프를 지켰다. agy 는 `.detail-page` 단독 선택자를
   병기해 범위를 넓혔는데, `layout_class` 가 항상 `adaptive` 라 쓰이지 않고 나중에 레이아웃이
   갈릴 때 의도치 않게 적용될 위험만 남는다.

**agy 안에서 가져올 것**

- **커버 범위**. agy 는 `usage-section` 과 `palette-section` 에도 좌우 반전을 적용했는데
  네 안은 `split-section` 만 다뤘다. 이미지와 텍스트가 나란히 놓이는 섹션이 그 셋이므로
  **세 곳 모두 `image-left`/`image-right` 가 동작해야 한다.**
- agy 안에 그 밖에 쓸 만한 처리가 있으면 판단해서 가져오되, **새 색 하드코딩과
  `.detail-page` 단독 선택자는 가져오지 마라.**

## 결과

### 변경 파일

- `web/detail_page.css`에 DTO variant 추가 규칙을 병합했습니다. 기존 `paper`·`light`·`dark`·`full-bleed` 규칙은 변경하지 않았습니다.
- 중간 산출물 `web/variants-codex.css`, `web/variants-agy.css`는 지시대로 삭제했습니다.

### agy 안의 대조·반영 결과

- 반영: `usage-section`과 `palette-section`의 `image-left`/`image-right` order 규칙을 가져왔습니다. 두 렌더러 분기는 모두 copy와 media를 형제 그리드 아이템으로 출력하므로, split-section과 같은 방향 전환만으로 실제 좌우 배치가 바뀝니다.
- 반영하지 않음: `#EAE1D6` 하드코딩과 `.detail-page` 단독 선택자는 제외했습니다. 병합본은 모두 `.detail-page--adaptive`로 한정하고, sand는 `yellow-500`·`jade-blue-50` 토큰의 `color-mix`만 사용합니다. `var(--ink)`도 사용하지 않았습니다.
- 반영하지 않음: agy의 full-bleed 재정의는 기존 variant 회귀 금지에 따라 제외했습니다. `detail_split`의 media 컨테이너에는 실제 이미지가 하나뿐이고 번호 목록 마크업도 없으므로, 동작하지 않는 이미지 stack/flex 및 번호 목록 규칙도 제외했습니다.

### variant 규칙 수

병합 블록의 CSS rule block 수(복수 selector는 한 rule block으로 계산)는 다음과 같습니다.

- `sand`: 5개
- `image-left`: 8개
- `image-right`: 6개
- `compact`: 11개

### 검증

- 렌더러에서 `block--{variant}` 클래스와 `split-section`, `usage-section`, `palette-section`의 실제 copy/media 구조를 다시 확인했습니다.
- base CSS만 로드한 일회성 Playwright 확인에서 774px 기준 split·usage·palette의 left/right 방향, detail split의 42:58 이미지/카피 비율, sand 색면, compact 2×2 전체 폭 테이블을 검증했습니다. 600px에서는 네 레이아웃이 단일 열로 전환됨을 확인했습니다.
- 토큰·정리 점검: 신규 블록에 `var(--ink)`/`#EAE1D6`가 없고, 두 중간 CSS 파일이 삭제됐음을 확인했습니다.
