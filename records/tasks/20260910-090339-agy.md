## 목표

검수자가 **한 화면에서 근거를 다 보고 바로 채점**할 수 있는 검수 페이지를 만든다.
산출물은 **`generated/evaluation/pilot-20260909-224737/review.html`** 하나다.

지금은 검수자가 폴더를 열어 PNG 를 하나씩 보고, `result_summary.json` 을 따로 읽고,
CSV 에 옮겨 적어야 한다. 그 왕복을 없애는 것이 이 작업이다.

## 먼저 읽을 것

- `docs/evaluation/human-review-guide.md` — 특히 2절(4대 축과 척도), 3절(축별 판정 기준),
  4절(배포 차단 조건 P0/P1), 5.2·5.3(2인 독립 검수와 합의 조건)
- `generated/evaluation/pilot-20260909-224737/run_index.json` — 6건의 메타
- 각 케이스의 `result_summary.json` — `product.page_plan` 에 카피가 들어 있다

## 페이지 구성

### 상단 고정 영역
- 4대 축(사실성·명료성·상품성·시각품질)의 **1점 / 3점 / 5점 판정 기준 요약**.
  가이드 3절에서 뽑되 검수 중 계속 보이도록 접이식으로 상단에 고정한다.
- **P0/P1 배포 차단 조건 5가지 체크리스트**. 가이드 4절 그대로.
  하나라도 걸리면 평균 점수와 무관하게 FAIL 이라는 점을 명시한다.

### 케이스별 영역 (6건)
각 케이스마다 다음을 한 화면에 배치한다.

1. **원본 이미지**와 **최종 상세페이지**(`detail_page.png`)를 나란히. 상세페이지는 세로로
   길어서 자체 스크롤 영역에 넣고, 클릭하면 원본 크기로 열리게 한다.
2. **photos 8장** 전부. 파일명의 역할(hero/packshot/detail/lifestyle/detail-02~05)을 캡션으로 달고,
   **생성 컷과 원본 보존 컷을 시각적으로 구분**하라. `lifestyle` 과 `detail-02` 이후는 모델이
   만든 참고 컷이고 `hero`/`packshot`/`detail` 은 원본 픽셀 기반이다.
   P0/P1 5번(참고용 라벨 누락)을 판정하려면 이 구분이 보여야 한다.
3. **카피 전문**을 읽을 수 있게 텍스트로 표시. `page_plan` 의 각 섹션마다
   `section_id`, `eyebrow`, `title`, `body`, `items` 를 순서대로. 이미지만 보고 사실성을
   판정할 수 없으므로 이게 없으면 페이지가 쓸모없다.
4. **분석 메타**: `product_type`, `display_name`, `is_traditional_craft`, `craft_type`,
   `classification_confidence`, `classification_reason`, `layout_id`
5. **채점 입력**: 4축 각각 1~5 라디오 또는 셀렉트, 코멘트 입력란,
   그리고 P0/P1 체크박스 5개.

### 채점 기록 방식
- 상단에 **검수자 이름 입력란**을 둔다 (A/B 구분용).
- 입력값은 **localStorage 에 자동 저장**한다. 실수로 새로고침해도 날아가지 않아야 한다.
- 하단에 **"CSV 행 복사"** 버튼을 둔다. 누르면 현재 입력을 `review_sheet.csv` 의 열 순서에
  맞는 행 텍스트로 만들어 클립보드에 복사한다. 열 순서는 그 CSV 의 헤더를 그대로 읽어 맞춰라
  (같은 디렉터리에 이미 생성돼 있다).
- **정본 기록은 CSV 다.** 페이지가 CSV 를 직접 쓰지는 않는다. 검수자가 붙여넣는다.

## 기술 제약

- **외부 CSS·JS·폰트를 쓰지 마라.** 자체 완결 단일 HTML 이어야 한다.
  이 페이지는 `file://` 로 로컬에서 열린다.
- 이미지는 같은 디렉터리 기준 **상대경로**로 참조한다 (`analysis-cma-XXXXX/photos/...`).
  절대경로를 쓰지 마라.
- 카피 텍스트는 `result_summary.json` 에서 읽어야 하는데, `file://` 에서는 fetch 가 막힌다.
  **빌드 시점에 JSON 내용을 HTML 안에 인라인으로 넣어라.** 페이지가 런타임에 파일을 읽으려
  하면 안 된다. 즉 이 작업은 파이썬 스크립트로 HTML 을 생성하는 형태가 된다 —
  생성 스크립트는 `scripts/build_review_page.py` 로 만들고, 그것이 위 HTML 을 출력하게 한다.
- 따라서 산출물은 두 개다: `scripts/build_review_page.py`(신규), 그것이 생성한 `review.html`.
