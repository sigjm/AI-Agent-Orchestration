## ② 에러 분석에 추가할 것

기존 6건에 더해 **이번 개선 과정에서 나온 것**을 같은 틀(증상 → 증거 → 원인 → 조치 →
재발 방지)로 추가하라. 오케스트레이터 자신의 오류도 숨기지 말고 적어라.

1. **합격 기준이 느슨해 통과 판정이 났다** — "고유 시퀀스 3종 이상, 중간 집합 3종 이상"이
   기준이었고 한 실행이 통과했다. 그런데 실제로는 페이지의 73%가 동일 블록이었고 두 쌍은
   집합이 100% 같았다. **"다른 게 하나라도 있나"만 세고 "얼마나 다른가"를 재지 않은 것**이
   원인이다. 조치로 `check_plan_diversity.py` 를 만들었다.
2. **원인 오진 두 건** — (a) 코드 패딩이 원인이라 보고 제거했으나 결과가 그대로였다.
   (b) 렌더러가 고정 슬롯에 끼워 넣는다고 단정했으나, 근거로 삼은 `{{THREE_GALLERY}}`·
   `{{TWO_GALLERY}}` 는 어느 템플릿에도 자리가 없는 **죽은 코드**였다. 실제 렌더러는
   `page_plan` 블록을 순서대로 돈다.
3. **선언만 있고 구현이 없던 값들** — DTO variant 8종 중 4종이 CSS 규칙 0개,
   `layout_id` 3종 중 `editorial-split` 이 CSS 0개. 계약에 값이 있으니 검증은 통과하는데
   화면은 안 바뀌는 종류의 결함이다.
4. **브리프 오류로 워커 작업이 무산된 사례 둘** — 오프라인 도구인 게이트 점검에 모델 서버
   확인을 선행 조건으로 넣어 작업이 중단됐고, 교차검증 두 워커에게 같은 파일을 수정하게 해
   충돌을 만들 뻔했다(중간에 정정). **지시하는 쪽의 오류도 결함 원인**이라는 점을 적어라.

기존 문서의 "관통하는 패턴" 절이 있다면 이 사례들이 그 패턴을 강화하는지 검토해 보강하라.
