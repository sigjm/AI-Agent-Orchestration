## 지시

## 작업 1 — `steps` 기본값을 4로 내린다 (먼저 처리)

네 수정으로 `steps` 가 실제로 반영되게 됐다. 잘 찾았다. 그런데 **부작용이 하나 생겼다.**

`src/local_detail_page_ai/clients.py:178` 의 기본값이 아직 `steps: int = 12` 다. 지금까지는
이 값이 무시돼 서버가 4로 돌았고, **우리가 가진 모든 실측치가 4스텝 기준**이다. 파라미터가
살아난 지금 다음 실행부터는 12스텝으로 간다.

네 실측으로 8스텝이 83.9초, 4스텝이 34.2초였다. 12스텝이면 장당 120초 안팎이고 페이지당
이미지가 7~8장이니 이미지 구간만 15분이 된다. 품질이 나아진다는 근거는 아직 없다.
Flux2 Klein 은 증류 모델이라 학습된 스텝 수를 벗어나면 오히려 나빠질 수 있고, 기존 A/B 는
파라미터가 죽어 있던 상태에서 돌린 것이라 무효다.

- 기본값을 **4** 로 바꾼다
- **왜 4인지 주석으로 남긴다**: Klein 은 4스텝 증류 모델이며 지금까지의 모든 실측이 이 값
  기준이라는 사실, 인상하려면 유효한 A/B 근거가 필요하다는 점
- 관련 테스트가 12를 기대하고 있으면 함께 정정한다

## 작업 2 — 산출물 문서 ③

새 문서 **`docs/deliverables/03-second-experiment-report.md`** 하나를 만든다.
1차 파일럿에서 발견한 결함에 대해 **가설을 세우고 고쳐서 2차로 검증한 과정**을 보고서로 정리한다.

### 다뤄야 할 실험 3건 — 전부 증거가 저장소에 있다

**실험 A — 컷아웃 마스크**
- 문제: 1차 파일럿(`generated/evaluation/pilot-20260909-191344`)에서 밝은 제품이 지워짐.
  ceramic(cma-122443) 보존율 3%, textile(cma-102980) 26%
- 가설: 연결성 없는 색거리 임계값이라 밝은 제품 내부가 배경으로 판정된다
- 조치: 배경을 이미지 테두리에서 4-이웃 flood fill 로 연결된 영역으로만 정의.
  파편화된 마스크는 `None` 반환 → 원본 fallback. 이후 그림자 억제 2차 수정
  (`src/detail_page_ai/source_photos.py`)
- 결과: 최종 재실행(`pilot-20260909-224737`)에서 **ceramic 64.1%, textile 96.8%, 6건 전건 OK**

**실험 B — 제품 유형별 씬 분기**
- 문제: 금·보석 목걸이가 금속 제품용 분기로 배정되어 사이드보드 씬을 받음
- 가설: `_product_scene_direction` 에 장신구 분기가 없어 metal 로 흘러간다
- 조치: 장신구 전용 분기 추가 + 키워드 커버리지 보강 (`src/detail_page_ai/prompts.py`)
- 결과: 재실행에서 **6건 전건 기대 분기 일치, 오분류 0건**
  (`scripts/check_scene_direction_coverage.py` 종료 코드 0)

**실험 C — 이미지 생성 파라미터**
- 문제: steps 를 올려 품질을 개선할 수 있는지 확인하려 했다
- 1차 실험: `generated/experiments/image-steps-ab-20260909-223049/`
  steps 4/8/16 × strength 0.25/0.50/0.75 = 9셀 → **9장의 SHA-256 이 전부 동일**,
  서버 로그는 전부 `steps=4`. 두 파라미터가 모두 무반영
- 원인: MLX Core 26.9.1 의 multipart `/v1/images/edits` 가 내부 `mode:"edit"` JSON 으로
  변환하면서 steps·strength 를 전달하지 않음
- 조치: edit 호출을 JSON `mode:"edit"` 경로로 전환 (`clients.py`)
- 결과: steps 반영 확인(8스텝 로그 8, 83.9초 vs 4스텝 34.2초, 해시 상이).
  **strength 는 여전히 무반영** — FLUX.2 in-context edit 모드가 의도적으로 쓰지 않음
- **남은 한계**: 파라미터가 살아난 뒤의 유효한 품질 A/B 는 아직 수행되지 않았다.
  스텝 인상이 품질을 올린다는 근거는 현재 없다

### 문서 구성

각 실험을 **문제 → 가설 → 조치 → 결과(수치) → 남은 한계** 틀로 정리하라.
1차와 2차 수치를 나란히 놓은 비교 표를 반드시 넣어라.

마지막에 **가설이 빗나간 지점**을 따로 적어라. 실험 C 는 "steps 를 올리면 품질이 오르는가"
라는 질문으로 시작했는데, 실제로 얻은 답은 "그 손잡이가 연결돼 있지 않았다" 였다.
그리고 strength 는 고칠 수 있는 문제가 아니라 모델이 지원하지 않는 기능이었다.
이런 결과를 실패로 숨기지 말고 그대로 적어라.
