## 지시

SGLang 서빙 운영 조사입니다. 관리자 결정: Ubuntu g6e.xlarge(NVIDIA L40S 48GB 1장, AWS)에서 텍스트(Qwen3.8-27B)와 이미지(FLUX.2-klein-9B)를 모두 SGLang 으로 서빙. `sglang serve` 는 프로세스당 모델 하나라 SGLang 프로세스 2개를 같은 GPU 에 띄운다. **코드는 건드리지 마세요.** 조사 문서만 씁니다. 브랜치 `deploy/ubuntu`, 커밋하지 마세요.

## 조사할 것 — 전부 출처(URL)를 붙이세요. 확인 못 한 것은 "확인 필요"로. 수치를 지어내지 마세요.
1. **텍스트 모델 가중치.** 로컬은 MLX 전용 `ddalcu/Qwen3.8-27B-MLX-Serve-4bit` 를 씁니다. CUDA 에서 SGLang 으로 올릴 수 있는 Qwen3.8-27B 가중치(원본 BF16, FP8, AWQ/GPTQ 4bit 등)가 Hugging Face 에 실제로 있는지, 저장소 ID, 각 파일 크기, 이미지 입력(비전) 지원 여부. 우리는 이미지를 넣어 분석하므로 **비전 입력이 되는 변형이어야 합니다.** 없으면 없다고 쓰고 가장 가까운 대안을 근거와 함께.
2. **이미지 모델 가중치와 라이선스.** FLUX.2-klein-9B 의 공식 저장소 ID, 크기, 그리고 **라이선스 — 상업적 사용 가능 여부**. 우리는 이커머스 상세페이지를 만듭니다. 9B 가 비상업 라이선스라면 반드시 명시하고, 4B 등 대안의 라이선스도 비교하세요. 게이트(동의 필요) 저장소인지, 다운로드에 HF 토큰이 필요한지.
3. **SGLang 설치 형태.** 공식 Docker 이미지 이름·권장 태그, CUDA 버전 요구, 확산 모델 지원이 포함된 설치 방법(추가 extra 필요 여부). L40S(Ada, compute capability 8.9) 지원 여부와 FP8 지원 여부.
4. **한 GPU 에 두 프로세스.** 텍스트 서버의 `--mem-fraction-static`, 확산 서버의 메모리 관련 인자(오프로드, `--num-gpus` 등). 두 프로세스가 GPU 한 장을 나눠 쓸 때 공식 안내나 알려진 이슈. 48GB 에 두 모델이 들어가는지는 **측정 전 추정만 가능**하니, 가중치 크기에서 계산한 하한만 쓰고 KV 캐시·활성화 메모리는 "측정 필요"로 두세요.
5. **FLUX.2-klein 편집 품질 이슈.** sgl-project/sglang issue #19449(9B 편집이 `--num-gpus 8` 에서 깨짐, 1장은 정상)의 현재 상태와 단일 GPU 영향.
6. **g6e.xlarge 사양.** vCPU·메모리·로컬 디스크(인스턴스 스토어 유무). 가격은 조사하지 마세요(이미 미검증 참고값으로 처리된 항목).

- **작성 및 변경 파일**:

  - `.orchestration/tasks/20260914-093132-agy2.md` (결과 보고 추가)

- **검증 방법**:
  - Hugging Face Model API(`curl -s https://huggingface.co/api/models/...`)를 통해 `Qwen/Qwen3.8-27B`, `Qwen/Qwen3.8-27B-FP8`, `cyankiwi/Qwen3.8-27B-AWQ-INT4`, `black-forest-labs/FLUX.2-klein-9B`, `black-forest-labs/FLUX.2-klein-4B`, `black-forest-labs/FLUX.2-klein-4b-fp8`의 실제 존재 여부, 파일 트리 크기, `gated` 상태 및 라이선스 태그를 실측 검증함.
  - Black Forest Labs 공식 블로그(`https://bfl.ai/blog/flux2-klein-towards-interactive-visual-intelligence`)를 직접 조회하여 9B는 비상업 라이선스(FLUX NCL), 4B는 Apache 2.0임을 확인.
  - GitHub API를 통해 `sgl-project/sglang` 공식 이슈 #19449 및 PR #19454의 상태(2026-03-04 머지 완료)와 단일 GPU(`--num-gpus 1`) 정상 작동 여부를 확인.
  - AWS EC2 공식 제품 상세 페이지(`https://aws.amazon.com/ec2/instance-types/g6e/`)를 파싱하여 `g6e.xlarge`의 vCPU(4), RAM(32 GiB), GPU(1x L40S 48GB), 로컬 NVMe SSD 인스턴스 스토어(1 x 250 GB)를 교차 검증.
  - Docker Hub API(`lmsysorg/sglang`) 및 SGLang 공식 저장소의 `docker/Dockerfile`, `docs/docs/sglang-diffusion/*`를 조회하여 공식 배포 태그(`v0.5.19`, `dev`), 빌드 구조(`BUILD_TYPE=all`), 서빙 CLI 인자 체계를 확인.

- **미해결 이슈 및 후속 워커 전달 사항**:
  1. **라이선스에 따른 모델 교체 결정**: 관리자 결정 지시사항에는 `FLUX.2-klein-9B`가 명시되었으나, 9B는 **상업적 사용 불가(FLUX Non-Commercial License)**이므로 이커머스 서비스에는 법적으로 사용할 수 없음. 동일 아키텍처의 상업 허용 대안인 **`FLUX.2-klein-4B` (Apache 2.0)**를 채택해야 함.
  2. **클라이언트 API 프로토콜 불일치**: 현재 `src/local_detail_page_ai/clients.py`의 `MlxServeImageClient`는 MLX Serve 전용 커스텀 JSON 포맷(`POST /v1/images/generations` with `mode: "edit"`)을 전송하므로, SGLang diffusion의 표준 OpenAI 규격(`POST /v1/images/edits` multipart)과 직접 호환되지 않음. docker-compose 작성 워커 또는 후속 코드 작업에서 어댑터/클라이언트 수정 필요.
  3. **VRAM 할당 비율 및 실제 인스턴스 실측 필요 항목**:
     - L40S 48GB는 실제 **44.70 GiB**입니다.
     - **기본 권장안(AWQ-INT4 19.60 GiB)**: 가중치 역산 하한 43.8%, 초안 `--mem-fraction-static 0.50`(약 22.35 GiB 선점), 확산 잔여 VRAM 22.35 GiB(FLUX 4B 차감 후 동적 여유 약 15.13 GiB).
     - **대안안(FP8 유지 28.77 GiB)**: 가중치 역산 하한 64.4%, 초안 `--mem-fraction-static 0.68`(약 30.40 GiB 선점), 확산 잔여 VRAM 14.30 GiB(FLUX 4b-fp8 3.80 GiB 결합 필수).
     - 배포 포트는 배포 계약에 맞춰 **텍스트 30000 (`sglang-text`)**, **이미지 30001 (`sglang-image`)**로 반영 완료.
     - 가중치 하한 기준 초안 비율 및 KV 캐시 슬롯, 확산 Denoising/VAE 동적 피크 VRAM, 이중 CUDA Context 오버헤드(총 ~2GB)는 인스턴스 기동 후 부하 테스트를 통해 최종 실측 확정 필요.
