## 지시

## 설계는 확정됐다. 구현만 하라.

설계 판단은 오케스트레이터가 끝냈다. 아래 사양을 그대로 구현하되, **사양이 코드와 충돌하면
멈추고 보고하라.** 임의로 설계를 바꾸지 마라.

## 배경

섹션 구성이 상품과 무관하게 수렴하는 문제를 프롬프트 문구로 두 차례 고쳤으나 한계에 왔다.
최신 실행(`pilot-20260910-115722`) 실측:

- 페이지의 **73%가 동일 블록** — `hero`·`feature_grid`·`detail_split`·`gallery`·`notice`·`closing` 6종이 6건 전부에 등장
- **평균 집합 일치도 78%**, box↔ceramic 과 jewelry↔furniture 는 **100% 동일**
- 바뀐 건 8칸 중 2칸뿐

문구를 더 다듬는 대신 **구체적 원형을 보여주는** 방식으로 전환한다.
`assets/references/detail-page-layouts.json` 에 25종 카탈로그가 있다
(`id`, `name`, `when`, `avoid_when`, `sequence`, `middle_count`, `rationale`, `source`).

## 구현 사양

### 1. 카탈로그 로더

`src/detail_page_ai/` 에 카탈로그를 읽는 최소 함수를 둔다. 모듈 수준 1회 로드 후 캐시.
파일이 없거나 깨졌으면 **예외를 던지지 말고 빈 목록을 돌려** 프롬프트가 원형 없이도
동작하게 하라. 참조 자산 하나 때문에 파이프라인이 죽으면 안 된다.

### 2. 결정적 선택 함수

```
select_layout_archetypes(image_sha256: str, user_hints, count: int = 4) -> list[dict]
```

- **필터**: `user_hints.making_method` 가 없으면 `sequence` 에 `statement` 가 든 원형을 제외한다.
  (이미 프롬프트에 건 `statement` 게이트와 같은 논리다. 없는 정보를 요구하는 원형을 보여주면
  모델이 그걸 채우려고 외형 묘사를 지어낸다.)
- **샘플링**: 남은 후보에서 `image_sha256` 을 시드로 `count` 개를 뽑는다.
  같은 해시 → 항상 같은 결과(재현 가능), 다른 해시 → 다른 결과.
  `random.Random(seed)` 로 충분하다. 후보가 `count` 보다 적으면 있는 만큼만.

### 3. 프롬프트 주입

`build_analysis_prompt(locale, user_hints, archetypes=None)` 로 인자를 추가하고,
`archetypes` 가 비어 있지 않을 때만 아래 성격의 블록을 프롬프트에 넣는다.

**제시 방식이 이 작업의 핵심이다. 다음을 반드시 지켜라.**

- **"고르라"가 아니라 "예시"다.** 넷 중 하나를 선택하라고 요구하지 마라.
  구조가 상품에 따라 이렇게 달라진다는 것을 보여주는 사례로 제시한다.
- **"넷 중 어느 것도 맞지 않으면 근거에 따라 다른 구성을 만들라"를 명시**하라.
- 각 원형은 `name`, `when`, `sequence` 정도만 싣는다. `rationale` 까지 넣으면 길어져
  기존 지시를 밀어낸다.
- **번호를 매기지 마라.** 1·2·3·4 로 매기면 순위나 순서로 읽힌다.

이 프롬프트는 이미 두 차례 개정으로 순서 각인을 걷어냈다. **같은 실수를 새 블록에서
반복하지 마라** — 목록이 순서를 가르치고 메뉴가 체크리스트가 되는 것이 지금까지의 실패 방식이다.

### 4. 호출부 연결

`src/local_detail_page_ai/adapters.py` 의 `LocalProductAnalyzer.analyze(image, mime_type, user_hints)`
는 이미지 바이트를 받는다. 여기서 `hashlib.sha256(image).hexdigest()` 를 구해
`_base_prompt` 를 거쳐 `build_analysis_prompt` 에 전달하라.

`ProductAnalyzer` 프로토콜 시그니처(`src/detail_page_ai/ports.py`)는 **바꾸지 마라.**
다른 구현체가 깨진다.

### 5. 테스트

`tests/test_prompts.py` 에 추가한다.

1. 같은 해시로 두 번 호출하면 같은 원형 집합이 나온다 (결정성)
2. 서로 다른 해시 여러 개로 호출하면 **적어도 두 개의 서로 다른 집합**이 나온다
3. `making_method` 가 없으면 선택된 원형에 `statement` 가 없다
4. 카탈로그 파일이 없어도 `build_analysis_prompt` 가 예외 없이 동작한다
5. 원형 블록에 번호(1. 2. 3.)가 들어가지 않는다

`.venv/bin/python -m pytest -q` 전체(현재 261+) 통과. 검사를 약화시키지 마라.

## 결과

### 변경 파일

- `src/detail_page_ai/layout_archetypes.py`
  - `assets/references/detail-page-layouts.json`을 모듈 로드 시 한 번만 읽어 캐시한다.
  - 파일 부재·인코딩/JSON 오류·entry 구조 오류는 빈 목록으로 처리한다.
  - `select_layout_archetypes(image_sha256, user_hints, count=4)`는 해시 시드의 `random.Random`으로 재현 가능한 샘플을 돌려주며, `making_method`가 없으면 sequence에 `statement`가 있는 원형을 제외한다.
- `src/detail_page_ai/prompts.py`
  - `build_analysis_prompt(..., archetypes=None)`의 선택 인자를 추가했다.
  - 원형이 있을 때만 name·when·sequence만을 번호 없는 예시로 주입한다. 이는 선택 메뉴가 아니며, 어느 예시도 맞지 않으면 근거에 따른 다른 구성을 만들도록 명시한다.
- `src/local_detail_page_ai/adapters.py`
  - `LocalProductAnalyzer.analyze()`에서 입력 이미지의 SHA-256을 계산해 선택된 원형을 `_base_prompt`를 거쳐 `build_analysis_prompt`로 전달한다. `ProductAnalyzer` 프로토콜은 변경하지 않았다.
- `tests/test_prompts.py`
  - 동일 해시 결정성, 다른 해시 간 집합 다양성, making_method 부재 시 statement 제외, 카탈로그 부재/구조 오류 복원력, 번호 없는 예시 주입을 검증하는 테스트를 추가했다.

### 검증 방법

- TDD: 새 원형 테스트를 먼저 실행해 모듈과 `archetypes` 인자가 없는 기존 상태에서 4개 실패를 확인한 뒤 구현했다. 이어서 entry 구조가 깨진 유효 JSON도 빈 목록이어야 한다는 회귀 테스트를 추가해 실패를 확인하고 로더 검증을 보강했다.
- `.venv/bin/python -m pytest -q tests/test_prompts.py` → `38 passed`
- `.venv/bin/python -m pytest -q` → `293 passed`
- 모델 호출 없이 `LocalProductAnalyzer._base_prompt()`를 호출해 해시 기반 예시 4개가 주입되고, 빈 `UserHintsDto`에서 statement가 포함된 원형이 없음을 확인했다.

### 미해결 이슈

- 지시대로 카탈로그 JSON은 수정하지 않았고 파일럿 재실행·모델 호출도 하지 않았다. 다음 파일럿에서 원형 예시가 블록 집합/개수 다양성 기준을 실제로 개선하는지 판정해야 한다.
- 카탈로그가 배포에서 누락되거나 손상되면 선택기는 빈 목록을 반환하고, 프롬프트는 원형 예시 없이 기존 안전 계약으로 계속 동작한다.
