## 반드시 담을 것

**① 빗나간 가설 네 개**

1. 코드 패딩이 원인이라 보고 제거했으나 결과가 그대로였다 → 원인은 프롬프트였다
2. 렌더러가 고정 슬롯에 끼워 넣는다고 단정했으나, 근거로 삼은 `{{THREE_GALLERY}}`·
   `{{TWO_GALLERY}}` 는 어느 템플릿에도 자리가 없는 **죽은 코드**였다.
   실제 렌더러는 `page_plan` 블록을 순서대로 돈다
3. "원형을 예시로 보여주면 모델이 다양하게 고를 것"이라 예상했으나 **오히려 악화**됐다
4. 참조 템플릿 이미지가 모델에 전달돼 형태를 강제한다고 의심했으나,
   `html_renderer.py` 에서 `del template_image` 로 버려진다

**② 합격 기준 자체가 틀렸던 사건**

초기 기준은 "고유 시퀀스 3종 이상, 중간 집합 3종 이상"이었고 한 실행이 통과했다.
그런데 실제로는 페이지의 73%가 동일 블록이었고 두 쌍은 집합이 100% 같았다.
**"다른 게 하나라도 있나"만 세고 "얼마나 다른가"를 재지 않은 것**이 원인이다.
그래서 `check_plan_diversity.py` 를 만들었다. 이 사건을 반드시 적어라.

**③ 6차의 시각 다양성 결과**

variant 분포가 처음으로 갈렸다. 이전에는 코드가 `detail_split`→`dark`,
`usage_scene`→`full-bleed` 로 고정 배정했다.

```
6차 출력: paper 22 · light 19 · image-left 4 · dark 3 · full-bleed 3 · image-right 2 · compact 1 · sand 0
```

**남은 문제**: 카탈로그에는 `sand` 가 39회 배정돼 있는데 출력에 0회다. 프롬프트가 원형의
`sequence` 만 싣고 `variants` 는 전달하지 않아, variant 는 여전히 모델이 고른다.
다른 워커가 지금 이 전달 경로를 고치고 있다. **미해결로 적어라.**

**④ 현재 미달 상태와 원인**

최신 판정은 평균 일치도 72.4%, 공통 블록 6종, 완전 일치 1쌍으로 **세 조건 모두 미달**이다.
원인 둘을 적어라 — 원형이 이미지 해시로 선택되어 두 상품이 같은 원형에 걸린 것,
그리고 공통 블록 계산에 DTO 가 강제하는 `hero`·`closing` 이 포함된 **기준 설계 착오**.
