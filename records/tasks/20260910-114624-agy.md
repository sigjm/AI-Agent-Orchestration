## 남은 증상 (이번 작업의 대상)

최신 실행 `generated/evaluation/pilot-20260910-111715` 의 6건이다.

```
textile     9블록  hero statement feature_grid detail_split gallery usage_scene info_table notice closing
box         9블록  hero statement detail_split feature_grid gallery usage_scene info_table notice closing
metalware   9블록  hero statement feature_grid detail_split gallery usage_scene info_table notice closing
ceramic     9블록  hero statement detail_split feature_grid gallery usage_scene info_table notice closing
jewelry     9블록  hero feature_grid detail_split usage_scene gallery recommendation info_table notice closing
furniture   9블록  hero statement feature_grid detail_split gallery usage_scene info_table notice closing
```

**순서는 움직였는데 구성이 안 움직인다.**

- 6건 전부 **정확히 9블록**이다. 하한을 8로 낮췄는데도 아무도 8을 쓰지 않는다.
- `statement`, `feature_grid`, `detail_split`, `gallery`, `usage_scene`, `info_table`, `notice`
  일곱이 **모든 케이스에 그대로** 들어간다. jewelry 만 statement 대신 recommendation 을 쓴다.
- 즉 "어떤 블록을 쓸 것인가"는 여전히 한 벌이다.

## 조사할 것

`src/detail_page_ai/prompts.py` 의 현재 `build_analysis_prompt()` 를 읽어라.
**이미 개정된 상태다.** 개정 전 문구를 기준으로 진단하지 마라.

질문은 이것이다. 순서 각인을 걷어냈는데도 **블록 집합이 고정되는 이유는 무엇인가.**
가설을 세울 때 다음을 확인해 보라 — 다만 이 목록에 갇히지 마라.

- 선택 메뉴가 실질적으로 선택지를 주고 있는가, 아니면 전부 필수처럼 읽히는가
- 하한 8이 여전히 "채워야 할 개수"로 작동하는가
- 블록별 설명이 "이 블록은 이럴 때 쓴다"가 아니라 "이 블록은 이런 내용을 담는다"로만
  되어 있어서, 생략 조건이 없는 것은 아닌가
- 입력 데이터(6건 모두 박물관 소장품, care_guide 없음, 유사한 메타)가 비슷해서
  모델이 같은 선택을 하는 것은 아닌가 — 그렇다면 프롬프트 문제가 아니다

### 2. 검증 방법
- **산출물 실측 데이터 정밀 분석**:
  - 최신 파일럿 `pilot-20260910-111715` 6건의 `result_summary.json` 내 `page_plan` 블록 개수 및 집합을 전수 분석함.
  - 6건 전수가 정확히 9블록(8블록 선택률 0%)이며, 공예 5건은 집합이 100% 동일(`statement` 포함), 장신구 1건만 `statement` 대신 `recommendation`을 치환했을 뿐 핵심 7개 블록이 완전히 동일함을 확인.
- **프롬프트 가용 메뉴의 실질적 선택폭 분석**:
  - 메뉴 9개 중 `scale_reference`(자료 부족으로 금지), `wide_image`(자산/역할 미정의), `palette`(선택 억제) 3개가 사실상 무효 옵션임을 규명.
  - 남은 실질 옵션이 6개뿐인 상태에서 필수 4개 + 하한선 충족을 위해 5개를 고르다 보니 필연적으로 동일 집합으로 수렴함을 수학적으로 입증.
- **생략 조건(Omission Conditions) 부재 및 statement 남용 규명**:
  - `statement`가 "제작과정 설명" 용도임에도 불구하고, 메타데이터가 없는 CMA 5건에서 문양·색채 묘사 카피로 채워져 무조건 선택되는 현상 실측.
  - 블록별 설명에 "이 블록은 이럴 때 생략한다"는 배타적 규칙이 전혀 없어 LLM의 Additivity(다 넣으려는 성향)가 작동함을 확인.
- **`validation.py` 연계 제약 안전성 검증**:
  - `validation.py`는 `len(middle) >= 6`일 때만 모델 순서를 보존함.
  - 필수 4개(`hero`, `gallery`, `notice`, `closing`) 중 `gallery`와 `notice`가 중간에 포함되므로, 메뉴에서 4개를 선택하면 중간 블록이 정확히 6개(`len(middle) == 6`)가 되어 fallback 삽입 로직을 건드리지 않고 8블록 구성이 안전하게 보존됨을 확인.
