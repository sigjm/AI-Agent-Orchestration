## 지시

## 배경

너와 agy 가 독립 진단한 결과를 오케스트레이터가 대조했다. **독립성 제약은 해제한다** —
`.orchestration/proposals/block-composition-agy.md` 를 읽어도 된다.

두 진단이 겹친 뼈대는 셋이다.

1. **8은 하한으로만 적혀 있어 "채워야 할 개수"로 작동한다.** 실제로 6건 전부 9블록을 냈다.
2. **블록별 설명에 생략·배제 조건이 없다.** "이 블록은 이런 내용을 담는다"만 있고
   "이럴 때는 쓰지 않는다"가 없어서 모든 블록이 항상 후보로 남는다.
3. **입력 동질성도 일부 원인이다** — 6건 모두 박물관 소장품에 care_guide·howMade 가 없다.
   다만 둘 다 "프롬프트 문제를 면제하지는 않는다"고 판단했고 나도 동의한다.

## 적용할 것

네 제안서의 A·B·C·D 와 agy 제안서의 1·2·3 을 합쳐 **최소 변경**으로 적용하라.

**반드시 채택**

- **8블록을 기본 예산으로 명시** (네 A, agy 1). 하한이 아니라 "먼저 8블록으로 짜고,
  아홉 번째는 기존 블록이 답하지 못하는 별개의 질문이 있을 때만 추가한다"는 구조로.
- **Copy Map 을 선택 목록이 아님을 명시** (네 B). 블록을 고른 뒤에 보는 참조표임을 분명히.
- **블록별 생략·선택 조건 도입** (네 C, agy 2). 특히 **`statement` 는 제작 과정
  (howMade) 데이터가 제공된 경우에만 포함**하고, 없으면 생략하도록. 외형 묘사로 채우지 말 것.
  나머지 선택 블록에도 각각 "언제 쓰고 언제 안 쓰는지"를 붙여라.

**조건부 채택 — 주의해서**

- agy 의 **아키타입별 메뉴 번들**은 방향은 맞지만 그대로 넣지 마라. 지난 차수에 네가
  아키타입별 고정 시퀀스를 "다른 형태의 고정 시퀀스를 만든다"는 이유로 거부했고 그 판단이 옳았다.
  이번에도 아키타입이 **고정 조합**이 되면 같은 문제가 개수만 바꿔 재발한다.
  아키타입은 **선호(preference)** 로만 쓰고, 최종 선택은 그 상품에서 실제로 관찰된 근거가
  정하게 하라.

어긋나는 지점은 네가 판단하되 **판단 근거를 결과 보고에 적어라.**

## 합격 기준 (다음 재생성으로 판정)

지난 차수 기준에 **구성 다양성**을 추가한다. 순서만 갈라지고 구성이 그대로여서 부분 통과였다.

1. 고유 시퀀스 **3종 이상** 그리고 최빈 빈도 **2/6 이하** (현재 3종 / 3-6)
2. **블록 개수가 최소 2종** 나온다. 현재는 6건 전부 9블록이다.
3. **중간 블록 집합이 최소 3종** 나온다. 현재는 5건이 동일 집합이다.
4. hero 첫 번째, closing 마지막, 허용 block_type, 14블록 이내 — 전건 유지
5. gallery 의 photo_ids 5개 계약, care_guide 없는 입력의 notice 문구 — 전건 유지

2·3 이 이번 차수의 본론이고 4·5 는 훼손 여부를 보는 관찰값이다.

**주의**: `validation.py` 는 중간 블록이 6개 미만이면 누락 블록을 채워 넣는다.
8블록 계획은 중간 6개라 경계에 딱 걸린다. **7블록 이하로 내려가면 fallback 이 작동해
원점으로 돌아간다.** 개정문이 그 아래로 유도하지 않도록 하라.

- `src/detail_page_ai/prompts.py`
  - 8~12 범위를 유지하되, hero·gallery·notice·closing과 근거를 통과한 네 middle block으로 **먼저 8블록을 설계**하고, 기존 블록이 답하지 못하는 별도 product-specific 질문이 있을 때만 9번째 이후를 추가하도록 했다.
  - Copy Map이 type을 고른 뒤에만 보는 참조표이며 inclusion list나 page-plan sequence가 아님을 명시했다.
  - reference guide가 page_plan의 고정 순서뿐 아니라 암묵적 block set도 요구하지 못하게 하고, 시각·카피 방향만 제공하도록 우선순위를 명시했다.
  - detail/grid/info/palette/recommendation/scale/statement/usage/wide_image 각각에 선택·생략 조건을 추가했다. 특히 statement는 creator-provided `making_method`(`howMade`)이 있을 때만 포함하고, 없으면 외형 묘사로 대체하지 않고 생략하게 했다.
  - 아키타입은 근거를 통과한 후보 사이의 tie-breaker일 뿐 고정 bundle이나 page order가 아님을 명시했다.

### 제안안 병합 판단

- agy 안의 8블록 anchor 및 strict omission 조건은 채택했다. `palette`·`wide_image`·`scale_reference`에도 사용·생략 기준을 추가해, 후보가 이름만 있고 실제 선택 불가능해지는 문제를 줄였다.
- agy의 아키타입별 4블록 고정 bundle은 채택하지 않았다. bundle은 순서가 아니더라도 상품군마다 동일한 block set을 다시 강제해 이번 합격 기준(중간 block set 3종 이상)을 훼손할 수 있다. 대신 archetype은 evidence-qualified 후보의 동점 해소 기준으로만 사용한다.
