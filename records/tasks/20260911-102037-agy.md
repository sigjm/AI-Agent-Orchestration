# 정답 집합을 냉동 산출물 기반으로 수정

## 지시

정답 집합에 구조적 결함이 있어 수정합니다.

## 문제

`scripts/audit_cutout_truth.py` 가 `SolidBackgroundCutoutExtractor` 를 **다시 실행해서** 판정을 만듭니다(28행 import). 그 결과 추출기 코드가 바뀌면 "정답"도 따라 바뀝니다. 정답 집합이 코드에 의존하면 정답 구실을 못 합니다.

실제로 codex 가 추출기를 고치자 당신의 테스트 2건이 깨졌습니다.

```
tests/test_cutout_truth.py::test_axis_b_remnant_distribution
  assert b_counts["none"] == 6  →  실제 7  (assert 7 == 6)
tests/test_cutout_truth.py::test_hidden_defects_missed_by_legacy_gate
```

`tests/test_cutout_regression.py` 2건도 같은 이유로 실패 중입니다.

## 고칠 것

1. **정답 집합은 냉동된 산출물에서 도출하세요.** `generated/evaluation/full60-20260910-204433` 의 `<case_id>/photos/01-hero.*` 와 `<case_id>/result_summary.json` 은 디스크에 고정돼 있어 코드가 바뀌어도 변하지 않습니다. 이것이 정답의 근거여야 합니다. 원본 이미지와 이 산출물을 비교해 판정하세요. 추출기를 다시 돌리지 마세요.

2. **테스트가 현재 상태를 불변식으로 못박지 않게 하세요.** `assert b_counts["none"] == 6` 같은 형태는 개선이 일어날 때마다 깨집니다. 정답 집합 문서가 서술하는 것은 **그 시점 산출물의 스냅샷**이므로, 테스트는 냉동 산출물에 대해 판정 로직이 일관되게 동작하는지를 검증해야지 특정 집계값을 고정해서는 안 됩니다.

3. `docs/evaluation/cutout-ground-truth.md` 의 내용 자체는 유지하세요. 수정 전 상태의 유효한 스냅샷이며 제가 codex 게이트를 채점하는 기준으로 이미 썼고 전 항목이 일치했습니다. 다만 문서 머리에 **이것이 어느 산출물 디렉터리의 어느 시점 스냅샷인지** 명시하세요.

## 건드리지 말 것

- `scripts/compare_cutout_regression.py` 는 추출기를 직접 호출하는 것이 **맞습니다.** 회귀 도구는 수정 전후를 재는 것이 목적이므로 코드에 의존해야 정상입니다. 이쪽은 설계대로입니다. 다만 `tests/test_cutout_regression.py` 의 실패 2건은 같은 "현재 상태 고정" 문제일 수 있으니 확인해서 고치세요.
- `src/detail_page_ai/source_photos.py` 는 codex 가 재작업 중입니다. 건드리지 마세요.
- `scripts/check_cutout_fidelity.py` 도 건드리지 마세요.
