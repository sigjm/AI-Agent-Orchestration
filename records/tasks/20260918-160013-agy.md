## 1. 빌더가 입력 인자를 제자리 변경한다 (가장 중요)

두 줄의 순서만 바뀌어도 조용히 깨지는 숨은 결합입니다.

이 줄을 지우세요.

## 2. 파이프라인이 해소를 명시적으로 하게 한다

`pipeline.py:310` 근처에서 지금은 빌더가 바꿔 놓은 `approved_draft.page_plan` 을
되읽습니다. 대신 `resolve_page_plan_photos` 를 **직접 불러** 그 결과를 쓰세요.

```python
available = {photo.photo_id for photo in sorted_photos}
resolved_plan = resolve_page_plan_photos(approved_draft.page_plan, available)
profile = profile.model_copy(update={"page_plan": resolved_plan})
```

빌더에는 지금처럼 `available_photo_ids` 를 계속 넘기면 됩니다(문서 자체의 해소는
빌더 안에서 일어나는 게 맞습니다).

경고 로그가 **블록당 정확히 1회**만 나오는 성질은 유지해야 합니다. 명시 호출로
바꾸면서 중복되지 않는지 확인하세요.

## 3. dto.py 의 방어 가드를 되돌린다

`AiBeProductPersistRequest.from_profile` 에 넣은 해소 로직과 함수 안 import 를
지우세요. 두 가지 이유입니다.

- 파이프라인에서 이미 해소된 profile 이 넘어오므로 **중복 해소**입니다.
- `dto.py` 가 `react_document_builder` 를 가져오는 것은 의존 방향이 거꾸로이고,
  순환 import 를 피하려고 함수 안에서 import 하는 것 자체가 그 신호입니다.

`from_profile` 호출부를 확인했습니다. 저장 요청 경로는 `pipeline.py:330` 하나
뿐이고 그 앞에서 해소가 끝납니다. 방어 가드가 막을 실제 경로가 없습니다.
