## 검수 결과

카탈로그는 계약을 전부 통과했다. 잘 만들었다.

- 20종, 고유 시퀀스 20개, 어휘 위반 0, 구조 위반 0

- `when`/`rationale` 이 실제 구매 근거와 자산 조건으로 갈린다

**보완할 지점이 하나 있다.**

## 문제: 길이 축이 죽어 있다

20개 중 **19개가 정확히 8블록**이고 9블록이 1개다. 브리프에 다양성 축으로 적었던
"정보 밀도 — 최소 8블록 압축형 / 12블록 상세형"이 실질적으로 쓰이지 않았다.

이게 왜 문제인가. 지금 고치려는 증상이 **"6건이 전부 9블록"** 이다. 참조 카탈로그가
"항상 8블록"을 가르치면 고정된 숫자가 9에서 8로 옮겨갈 뿐 다양성은 생기지 않는다.
카탈로그는 **길이도 상품에 따라 달라진다**는 것을 보여줘야 한다.

## 작업

`assets/references/detail-page-layouts.json` 에 **길이 분포를 만든다.**

- 기존 20종을 지우거나 대폭 손대지 마라. 내용은 좋다.
- **10~12블록 상세형을 최소 5종 추가**하라. 총 25종 이상이 된다.
- 추가하는 상세형은 8블록형의 확장판이 아니라 **처음부터 다른 상황**이어야 한다.
  예를 들어 원본 자산이 여러 각도로 많이 확보된 경우, 구성품이 많아 각각 설명이 필요한 경우,
  크기·색·질감이 모두 구매 근거인 경우처럼 **정보량 자체가 많은 상품**이다.
  `when` 에 "왜 이 상품은 블록이 더 필요한가"가 드러나야 한다.
- 기존 항목 중 8블록이 부자연스러운 것이 있으면 그것만 조정하라. 억지로 늘리지 마라.

목표 분포는 대략 8블록 절반, 9~10블록 3분의 1, 11~12블록 나머지다. 정확히 맞출 필요는 없고
**한 숫자에 몰리지만 않으면 된다.**

## 테스트 보강

`tests/test_layout_catalog.py` 에 다음을 추가하라.

1. 서로 다른 시퀀스가 **25종 이상**이다
2. **블록 길이가 최소 4종** 나온다 (예: 8, 9, 10, 12)
3. **어느 한 길이도 전체의 60% 를 넘지 않는다** — 이번에 19/20 = 95% 였던 상황을 막는다

`.venv/bin/python -m pytest -q` 전체 통과 확인.
