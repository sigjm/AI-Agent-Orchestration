## 지시

# 배경

인프라팀이 Stage L40S 에서 상세페이지 텍스트 서버가 메모리 문제로 못 뜬다고 알려왔다.
요청 중 두 가지가 **실측**이다.

1. 텍스트 모델만 실행해서 로딩 후, 실제 생성 중 최대 VRAM
2. 이미지 모델만 실행해서 로딩 후, 실제 이미지 생성 중 최대 VRAM

L40S 를 쓰려면 Stage 워크로드를 멈춰야 해서 **GPU 를 쓸 수 있는 시간이 짧다.** 그 시간에 실수 없이
한 번에 측정하도록 스크립트를 미리 만들어 둔다. 지금 우리 쪽엔 GPU 가 없으니 **실행 검증은 문법·로직까지만** 한다.

# 할 일 — `scripts/runtime/measure_vram.sh` (신규)

- 독립 bash 스크립트. 저장소 파일을 import 하지 않는다. GPU 파드 안의 page-generation 컨테이너에
  `kubectl cp` 로 넣어 바로 실행할 수 있어야 한다 (이미지에는 `scripts/runtime/render_detail_page.mjs` 만 들어간다).
- 사용법: `measure_vram.sh text <샘플이미지.jpg>` / `measure_vram.sh image <샘플이미지.jpg>`

## 서버 기동 명령은 **프로덕션과 똑같아야** 측정이 의미가 있다

명령을 스크립트에 다시 적지 마라. entrypoint 의 DRY_RUN 출력을 재사용해라.

    DRY_RUN=1 /usr/local/bin/detail-page-ai-entrypoint
    → TEXT: HF_HUB_OFFLINE=1 sglang-python -m sglang.launch_server --model-path ... (printf %q 로 이스케이프됨)
    → IMAGE: ...

`TEXT:`/`IMAGE:` 접두사를 떼고 실행하면 프로덕션과 같은 인자로 뜬다. 컨테이너 env(TEXT_MEM_FRACTION 등)도
그대로 반영된다. 출력 형식은 `deploy/sglang/entrypoint.sh` 의 `print_command` 를 직접 확인해라.

## 측정 흐름 (모드별)

1. `nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits -lms 500` 을 백그라운드로 CSV 에 기록
2. 기동 전 값(baseline)
3. 서버 기동 → `/v1/models` 200 대기 (타임아웃 있게, 서버가 죽으면 즉시 실패)
4. 로딩 후 값(loaded)
5. **실제 요청 1건** — 프로덕션과 같은 형태로:
   - text: `/v1/chat/completions` 에 샘플 이미지를 넣은 요청 (비전 prefill 이 VRAM 을 가장 많이 쓴다)
   - image: 프로덕션이 쓰는 엔드포인트·크기로 1건. `src/local_detail_page_ai/clients.py` 를 읽고
     `/v1/images/generations` 와 `/v1/images/edits` 중 무엇을 어떤 크기로 부르는지 확인해서 맞춰라
6. 요청 중 최대값(peak) = 요청 구간 CSV 의 최댓값
7. 서버 종료, 샘플러 종료
8. 요약 한 줄: `mode baseline_MiB loaded_MiB peak_MiB request_ok elapsed_s` 와 CSV 경로

## 주의

- 서버가 죽거나 요청이 실패하면 **숫자를 내지 말고** 실패로 끝내라. 실패한 측정이 성공처럼 보이면 안 된다
- 종료 시 띄운 프로세스는 반드시 정리 (trap)
- macOS 에 `timeout` 명령이 없다는 건 신경 쓰지 않아도 된다 — 이건 리눅스 컨테이너에서 돈다
