# hero 를 원본 사진으로 고정

- 워커: codex
- 발행: 2026-09-12 02:50:48
- 지휘: Claude Code (오케스트레이터 세션)

## 지시

hero 컷이 항상 원본 사진을 쓰도록 바꿉니다.

## 요구

관리자 지시: **hero 는 배경을 제거한 합성본이 아니라 원본 사진을 그대로 쓴다.**

현재 `src/detail_page_ai/source_photos.py:617-637` 에서 hero 는 `preserve_arrangement` 가 참일 때만 `_source_fallback` 을 타고, 거짓이면 `_composite(..., background=self._solid_background("#F7F7F5"))` 로 배경을 갈아끼웁니다. hero 는 이 분기와 무관하게 항상 원본을 쓰게 하세요.

**packshot, detail 등 나머지 역할은 건드리지 마세요.** 지금 동작을 유지합니다.

## 반드시 해결해야 하는 것 — 메타데이터 의미 충돌

`_source_fallback`(`:909-933`)은 `asset_mode="source"`, `fidelity_status="FALLBACK"` 을 답니다. 이 값의 의미는 **"컷아웃을 시도했으나 실패해서 원본으로 물러섰다"** 입니다.

hero 가 의도적으로 원본을 쓰는 것은 실패가 아니라 **설계된 선택**입니다. 그런데 같은 `FALLBACK` 을 달면 다음 문제가 생깁니다.

- `scripts/check_cutout_fidelity.py` 가 `FALLBACK`/`asset_mode=source` 를 "컷아웃 미수행"으로 판정합니다. hero 를 기준(`--role hero`)으로 재기 때문에, **모든 케이스가 전건 미수행으로 찍혀 게이트가 무의미해집니다.**
- 이 게이트는 방금 한 차수를 들여, 9차수 동안 숨어 있던 폴백 85%를 드러내려고 만든 것입니다. 그 신호를 죽이면 안 됩니다.

따라서 **의도된 원본 사용과 컷아웃 실패를 구분할 수 있어야 합니다.** 구체적 방식은 당신이 판단하세요. 새 `asset_mode` 값을 추가하든, `fidelity_status` 를 달리 주든, 별도 필드를 두든 좋습니다. 판단 기준은 이것입니다.

- 게이트가 "hero 가 원본인 것은 설계대로다"와 "컷아웃이 실패했다"를 구분할 수 있어야 한다.
- 라벨은 **붙이면 안 됩니다.** hero 는 AI 생성물이 아니라 원본이므로 '참고용' 표시 대상이 아닙니다. 현재 `_labels["hero"]` 는 `"원본 보존 대표 이미지"` 이며 이대로가 맞습니다.
- `product_generated` 는 `False` 유지.

DTO 에 값을 추가하면 `AssetMode`/`FidelityStatus` 리터럴 정의와 BE 로 나가는 계약(`GeneratedPhotoMetadataDto`)에 함께 반영되어야 합니다. **하위 호환을 깨지 마세요** — 기존 값을 소비하는 쪽이 있습니다. `src/detail_page_ai/backend_client.py:126-141` 의 사진 전달 필터가 `fidelity_status` 를 검사하므로 hero 가 그 필터에서 탈락하지 않는지 반드시 확인하세요. 탈락하면 BE 가 hero 를 못 받습니다.

## 게이트 쪽

`scripts/check_cutout_fidelity.py` 도 새 구분을 이해하도록 함께 고치세요. hero 가 설계상 원본이면 그것을 "미수행"으로 세지 말고, 실제 컷아웃 실패만 미수행으로 세야 합니다. 컷아웃 수행률을 무엇을 기준으로 계산할지 다시 정하고, 근거를 주석에 남기세요.

## 결과

### 변경 파일

- `src/detail_page_ai/models.py`: 하위 호환을 유지하며 `AssetMode`에 `source_original`을 추가했습니다. `FeProductPhotoDto`와 `GeneratedPhotoMetadataDto`가 이 공통 타입을 참조하므로 FE/BE 메타데이터 계약에도 자동 반영됩니다.
- `src/detail_page_ai/source_photos.py`: cutout 성공/실패 및 `preserve_arrangement` 값과 무관하게 hero는 원본 바이트를 그대로 쓰도록 했습니다. 다중 원본 입력 경로도 동일합니다. `source_original`은 hero 전용이며 `VERIFIED`, `product_generated=False`, 기존 라벨 `원본 보존 대표 이미지`를 사용합니다. 검증기는 이 모드가 hero/VERIFIED이고 원본 SHA-256과 바이트가 일치할 때만 허용합니다. packshot·detail 등 다른 역할의 기존 분기는 유지했습니다.
- `scripts/check_cutout_fidelity.py`: `source_original`/`VERIFIED` hero는 `원본 사용(설계)`로 별도 기록하고 미수행/메타데이터 누락에서 제외했습니다. 실제 `source` 또는 `FALLBACK`은 계속 `컷아웃 미수행`입니다. 수행률은 "실제 시도"(`VERIFIED source_composite/source_crop` 성공 + `source/FALLBACK` 실패)만을 분모로 하며, 설계상 원본 건수·시도 건수·분모 근거를 요약에 추가했습니다.
- `tests/test_source_photos.py`, `tests/test_eval_scripts.py`: 원본 hero의 바이트/라벨/메타데이터, 실제 폴백의 유지, 설계상 원본이 게이트의 미수행·수행률 분모에서 제외되는지를 추가 검증했습니다. 원본 hero의 합성 transform 전제를 제거하고 화면 내 제품 점유율 기준으로 기존 lifestyle 테스트를 조정했습니다.

### BE 전달 필터

통과합니다. `backend_client.py` 필터는 `VERIFIED` 상태, `product_generated=False`, 비어 있지 않은 `source_sha256`인 hero를 허용합니다. `source_original` hero는 모두 충족합니다. 기존 `test_persist_sends_generated_product_photos_when_available`도 multipart hero 포함을 통과했습니다.

### 게이트 검증

실행:

```bash
.venv/bin/python scripts/check_cutout_fidelity.py \
  generated/evaluation/full60-20260910-204433 --role hero \
  --json /tmp/full60-hero-gate.json
```

출력 요약:

```text
총 60건 | OK: 3건 | 부분 손실: 4건 | 심각 손실: 0건 |
컷아웃 수행: 9/60건 (15.0%) | 컷아웃 미수행: 51건 | 배경 잔존: 2건
최종 판정: [FAIL] 배경 잔존(BACKGROUND_RESIDUE: 2건) 및

```

저장된 60건은 과거 `source/FALLBACK` 메타데이터이므로 51건 미수행이 유지됩니다. 이는 새 hero 정책을 과거 산출물에 소급 적용한 결과가 아니라, 실제 실패를 그대로 보존해 표시한 것입니다. 새 산출물의 `source_original` hero는 같은 게이트에서 `원본 사용(설계)`으로 기록되어 미수행 및 수행률 분모에 포함되지 않습니다.
