## 지시

## 목표

상세페이지 레이아웃 원형 **20종 이상**을 구조화된 데이터로 만든다.
새 파일 두 개만 만든다.

- `assets/references/detail-page-layouts.json` — 카탈로그
- `tests/test_layout_catalog.py` — 카탈로그가 계약을 지키는지 검증

## 배경 (왜 필요한가)

이 서비스는 상품마다 다른 섹션 구성을 내야 하는데, 실측 결과 **6건이 거의 같은 구성**으로
수렴한다. 원인 진단과 프롬프트 개정을 두 차례 했고 순서는 갈라졌지만 구성은 아직 한 벌이다.
모델에게 "다양하게 하라"고 말하는 것만으로는 부족하다는 것이 확인됐다. **실제로 서로 다른
레이아웃이 어떤 것인지 구체적 원형으로 보여주는 참조 데이터**가 필요하다.

## 어휘 (반드시 이 안에서만)

`src/detail_page_ai/dto.py` 의 `BlockType` 이 허용하는 값은 정확히 13개다.

```
hero, statement, feature_grid, detail_split, wide_image, gallery,
usage_scene, scale_reference, palette, recommendation, info_table, notice, closing
```

이 밖의 이름을 지어내지 마라. DTO 규칙도 지켜야 한다: **hero 가 첫 번째, closing 이 마지막,
전체 14블록 이하.** 그리고 `src/detail_page_ai/validation.py` 는 중간 블록(hero·closing 제외)이
**6개 미만이면** 누락 블록을 채워 넣으므로, 중간 블록이 6개 미만인 레이아웃은 실제로는
그 fallback 에 덮인다. 카탈로그에 넣더라도 그 사실을 항목에 표시하라.

## 각 항목에 담을 것

```json
{
  "id": "texture-macro-led",
  "name": "질감 접사 중심",
  "when": "표면 질감·직조·양각이 제품의 핵심이고 원본에 접사가 확보된 경우",
  "avoid_when": "제품이 작아 접사가 형태를 알아보기 어렵게 만드는 경우",
  "sequence": ["hero", "detail_split", "gallery", "feature_grid", "usage_scene", "info_table", "notice", "closing"],
  "middle_count": 6,
  "rationale": "형태보다 표면이 구매 근거이므로 접사를 앞세우고 전체 컷은 뒤에서 맥락을 준다",
  "source": "관행 | 프로젝트 가이드 | 실측"
}
```

`middle_count` 는 계산해서 넣어라. `source` 는 근거의 출처를 밝혀라 —
프로젝트의 기존 가이드(`src/detail_page_ai/reference_guide.py`, `assets/references/`)에서
온 것인지, 일반적인 커머스 관행인지, 네 판단인지.

## 20종을 만드는 방법 — 중요

**하나의 시퀀스를 뒤섞어 20개로 부풀리지 마라.** 그건 다양성이 아니라 순열이다.
서로 다른 축에서 출발해야 진짜로 다른 레이아웃이 나온다. 예를 들어 이런 축들이 있다.

- **무엇이 구매 근거인가** — 형태 / 표면 질감 / 크기 / 색 조합 / 구성품 수 / 제작 과정 / 사용 맥락
- **원본 자산이 무엇인가** — 접사만 있음 / 전체 컷만 있음 / 여러 각도 확보 / 한 장뿐
- **정보 밀도** — 최소 8블록 압축형 / 12블록 상세형
- **제품 성격** — 단품 / 세트 / 크기 비교가 필요한 것 / 색이 핵심인 것

각 항목이 **왜 다른 항목과 다른지**가 `when` 과 `rationale` 에서 드러나야 한다.
두 항목의 `sequence` 가 같으면 둘 중 하나는 지워라.

## 검증 테스트

`tests/test_layout_catalog.py` 에 최소 다음을 넣어라.

1. 모든 `sequence` 가 13개 허용 어휘만 쓴다
2. 모든 항목이 hero 로 시작하고 closing 으로 끝나며 14블록 이하다
3. `middle_count` 가 실제 시퀀스와 일치한다
4. `id` 가 중복되지 않는다
5. **서로 다른 `sequence` 가 20종 이상이다** (중복 시퀀스가 있으면 실패)
6. 필수 키(`id`, `name`, `when`, `sequence`, `rationale`)가 모두 있다

`.venv/bin/python -m pytest -q` 전체(현재 261개) 통과해야 한다.
