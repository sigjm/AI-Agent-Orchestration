# 갤러리 photo_ids를 코드가 확정하도록 단일화

- 워커: agy
- 발행: 2026-09-23 11:20:12
- 지휘: Claude Code (오케스트레이터 세션)

## 지시

# 배경

상세페이지 파이프라인에서 FLUX로 만든 생성컷(detail-02 ~ detail-05, lifestyle-02)이
계속 버려지고 있다. 실제 두 번의 실사 실행에서 모두 미사용 5장이 나왔다.

원인은 갤러리 블록의 photo_ids를 **모델 출력에 맡기고 있기 때문**이다. 모델은
`["hero"]` 또는 `["hero","detail"]` 같이 규약과 다르게 채운다.

그런데 PNG 렌더러는 이미 이 문제를 코드로 우회하고 있다.

  src/detail_page_ai/html_renderer.py:358-369

  detail_slots = ("detail","detail-02","detail-03","detail-04","detail-05")
  if any(pid in photo_uris for pid in ("detail-02","detail-03","detail-04","detail-05")):
      requested = [pid for pid in detail_slots if pid in photo_uris]   # ← 모델 출력 무시
  else:
      requested = block.photo_ids or list(detail_slots)

즉 PNG는 생성컷을 쓴다. 반면 react_document_builder 는 이 로직이 없어서
block.photo_ids 를 그대로 따른다. 그 결과 **같은 실행인데 두 산출물이 갈린다.**

  렌더된 sections/gallery.png        → 이미지 5장
  react_document (BE·FE가 받는 것)   → 이미지 1장

판매자가 미리보기에서 본 페이지와 실제 저장·노출되는 페이지가 달라진다.

# 할 일

갤러리 슬롯 결정 로직을 **한 곳으로 모으고 두 렌더 경로가 같이 쓰게 한다.**
새 로직을 만드는 게 아니라, html_renderer 에 이미 있는 정책을 공용화하는 작업이다.

1. 새 모듈 `src/detail_page_ai/photo_slots.py` 를 만든다. 내용은 최소로:

   - `GALLERY_SLOTS = ("detail","detail-02","detail-03","detail-04","detail-05")`
   - `GENERATED_DETAIL_SLOTS = GALLERY_SLOTS[1:]`
   - `resolve_gallery_photo_ids(requested, available) -> list[str]`
     정책은 html_renderer 의 현행 동작과 **동일**하게:
       · available 에 생성 디테일컷(GENERATED_DETAIL_SLOTS)이 하나라도 있으면
         → GALLERY_SLOTS 중 available 에 있는 것 전부를 순서대로 반환 (requested 무시)
       · 없으면 → requested 중 available 에 있는 것, 그것도 비면
         GALLERY_SLOTS 중 available 에 있는 것
     중복 제거, 최대 5장.

2. `html_renderer.py` 의 gallery 분기가 이 함수를 쓰도록 바꾼다.
   **렌더 결과는 달라지면 안 된다.** 동작 동일, 중복 제거가 목적이다.

3. `react_document_builder.py` 의 `_photo_ids()` 에서 `block.block_type == "gallery"`
   인 경우 이 함수를 쓰도록 한다. available_photo_ids 가 None 이면 현행대로 둔다.

4. `("detail","detail-02",...)` 리터럴이 여러 곳에 흩어져 있다.
   backend_client.py:140, source_photos.py:567-570, validation.py:231 등.
   **이번 작업에서는 html_renderer 와 react_document_builder 두 곳만** 공용 상수로
   바꾼다. 나머지는 손대지 마라. 범위를 넓히지 말 것.

# 테스트

tests/test_react_document.py 에 회귀 테스트를 추가한다. 최소 2개:

  - 생성컷이 available 에 있으면, 모델이 photo_ids=["hero"] 를 줬더라도
    react_document 갤러리가 detail~detail-05 를 참조한다
  - 생성컷이 전혀 없으면 종전 동작(모델 photo_ids 존중)이 유지된다

그리고 **PNG 와 react_document 가 같은 사진 집합을 쓰는지** 확인하는 테스트를
하나 추가한다. 이게 이번 작업의 핵심이다.

# 제약

- 기존 테스트를 통과시키려고 약화시키지 마라. 깨지면 왜 깨지는지 보고할 것.
- DTO 를 제자리에서 변형(mutate)하지 마라. 필요하면 model_copy 를 쓴다.
- dto.py 에 역방향 import 를 추가하지 마라. photo_slots.py 는 아무것도 import 하지 않는
  순수 모듈이어야 한다.
- 프롬프트(prompts.py)는 건드리지 마라. 모델에게 계속 규약을 알려주되,
  코드가 최종 결정권을 갖는 구조다.

### 1. 변경 파일 목록 및 변경 사유

1. **`src/detail_page_ai/photo_slots.py` (신규 생성)**
   - **무엇을**: `GALLERY_SLOTS = ("detail", "detail-02", "detail-03", "detail-04", "detail-05")`, `GENERATED_DETAIL_SLOTS = GALLERY_SLOTS[1:]`, `resolve_gallery_photo_ids(requested, available) -> list[str]` 함수 구현.
   - **왜**: 갤러리 슬롯 결정 정책을 단일 모듈로 분리하여 HTML/PNG 렌더러와 React Document 빌더가 동일한 로직을 공유하게 함. `dto.py`나 프로젝트 모듈을 일체 import하지 않는 순수 모듈로 구성.

2. **`src/detail_page_ai/html_renderer.py` (수정)**
   - **무엇을**:
     - `photo_slots` 모듈에서 `GALLERY_SLOTS`, `GENERATED_DETAIL_SLOTS`, `resolve_gallery_photo_ids` import.
     - fallback plan의 갤러리 블록 `photo_ids` 리터럴을 `list(GALLERY_SLOTS)`로 교체.
     - `block_type == "gallery"` 분기의 인라인 슬롯 결정 로직을 `resolve_gallery_photo_ids(block.photo_ids, photo_uris)`로 단일화.
     - `photo_uris` 생성 필터의 생성 디테일컷 리터럴 튜플을 `GENERATED_DETAIL_SLOTS`로 교체.
   - **왜**: 렌더 동작과 출력 결과를 기존과 100% 동일하게 유지하면서 중복 하드코딩을 제거하고 공용 함수를 사용하도록 통일.

3. **`src/detail_page_ai/react_document_builder.py` (수정)**
   - **무엇을**:
     - `photo_slots` 모듈에서 `GALLERY_SLOTS`, `resolve_gallery_photo_ids` import.
     - `_photo_ids()` 함수에서 `block.block_type == "gallery"`이고 `available_photo_ids is not None`인 경우, `resolve_gallery_photo_ids(candidates, available_photo_ids)`를 호출하여 슬롯을 확정하도록 분기 추가.
     - `available_photo_ids is None`인 경우에는 기존 동작을 그대로 유지.
     - 갤러리 슬롯 최대 개수를 `len(GALLERY_SLOTS)`로 지정.
   - **왜**: 모델 출력이 `["hero"]` 등 비정상 photo_ids를 제공하더라도 FLUX 생성컷이 있을 때 버려지지 않고 `detail`~`detail-05`가 react_document AST에 정상 반영되도록 함.

4. **`tests/test_react_document.py` (수정)**
   - **무엇을**: 회귀 테스트 3종 추가.
     - `test_gallery_uses_generated_detail_cuts_when_available_ignoring_model_request`: 생성컷이 available에 있을 때 모델이 `photo_ids=["hero"]`를 줬어도 react_document 갤러리가 `detail`~`detail-05`를 참조하는지 검증.
     - `test_gallery_preserves_model_photo_ids_when_no_generated_cuts_available`: 생성컷이 없을 때 모델이 지정한 `photo_ids`를 존중하는 종전 동작이 유지되는지 검증.
     - `test_png_and_react_document_use_same_gallery_photos`: 동일한 draft 및 photo set 입력 시 HTML(PNG 렌더러 소스)과 react_document가 정확히 동일한 사진 집합 및 순서(`["detail", "detail-02", "detail-03", "detail-04", "detail-05"]`)를 참조하는지 검증.
   - **왜**: 두 렌더 경로 간 사진 참조 불일치 방지 및 회귀 방지.
