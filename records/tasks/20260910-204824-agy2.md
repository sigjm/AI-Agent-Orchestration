주 문서는 오늘 00:11 에 작성됐고 그 뒤 17개 커밋이 들어갔습니다. 아래가 이관에 영향을 주는 변경입니다. 각 항목이 AWS 이관 준비물에 어떤 영향을 주는지 확인해서 반영하세요.

- `src/detail_page_ai/layout_archetypes.py` 와 `assets/references/detail-page-layouts.json` — 신규 자산입니다. 컨테이너 이미지에 포함돼야 합니다.

- `scripts/` 가 `dataset/`, `runtime/`, `browser/`, `orchestration/` 하위로 재편됐습니다. 기존 문서의 스크립트 경로가 낡았을 수 있으니 전부 실제 경로로 확인하세요.
- `src/local_detail_page_ai/factory.py` 로 어댑터 조립이 옮겨졌습니다.

## 문서에 반드시 담을 것

1. **이관 준비물 체크리스트.** 사람이 순서대로 밟을 수 있는 형태로. 각 항목은 "무엇을 준비하는가 / 없으면 무엇이 막히는가 / 확인 방법" 세 가지를 갖춰야 합니다.
2. **가장 큰 제약을 정면으로 다룰 것.** 현재 추론은 Apple Silicon 전용 MLX 서버(`127.0.0.1:11234`)에 물려 있습니다. AWS 로 가면 이 서버가 그대로 갈 수 없습니다. 텍스트 모델과 이미지 모델 각각에 대해 무엇으로 대체해야 하는지, 그때 우리 클라이언트 코드에서 무엇이 깨지는지 구체적으로 쓰세요. 특히 위에 적은 이미지 편집 호출 규약이 대체 서버에서 어떻게 되는지가 핵심입니다.
3. **환경변수 정본 표.** `src/detail_page_ai/config.py` 의 `Settings` 를 실제로 읽어서, alias(대문자 환경변수명), 기본값, AWS 에서 반드시 바꿔야 하는지 여부를 표로 만드세요. 문서에 이미 8절이 있으니 현재 코드와 대조해 틀린 것을 고치세요.
4. **상태(state) 처리.** SQLite 기반 job repository 와 delivery outbox 가 컨테이너 재시작·수평 확장에서 어떻게 되는지. 이미 7절이 있으니 현재 `persistence.py` 와 대조하세요.
5. **검증 절차.** 기존 10절의 단계별 절차를 현재 스크립트 경로와 신규 게이트(`check_reference_label.py`, `check_plan_diversity.py`, `check_cutout_fidelity.py`)를 포함하도록 갱신하세요.
6. **아직 결정되지 않은 것.** 우리가 정할 수 없는 항목(인스턴스 타입 승인, 모델 가중치 저장 위치, BE 엔드포인트 주소 등)은 추측해서 채우지 말고 '결정 필요' 목록으로 분리하고 누가 결정해야 하는지 적으세요.

## 제약

- 우리 팀은 생성형 AI 팀입니다. FE 배포나 프런트엔드 연동은 범위 밖입니다. AI 서비스와 추론 서버까지만 다루세요.
- 실제로 검증하지 않은 수치를 쓰지 마세요. GPU 사이징이나 처리량을 새로 지어내지 말고, 기존 문서의 산정 근거를 인용하거나 '측정 필요'로 남기세요.
- 참고 실측치: 이번 세션 기준 6건 파일럿이 이미지 생성 포함 약 27분, 1건당 약 226초였습니다(Apple Silicon MLX, Qwen3.8-27B-4bit 18.2GB + flux2-klein-9b-4bit 9.5GB). 이것은 AWS 성능이 아니라 현재 로컬 기준선입니다. 그렇게 명시해서 쓰세요.
