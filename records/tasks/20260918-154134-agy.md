# page_plan 의 없는 사진 참조 없애기

- 워커: agy
- 발행: 2026-09-18 15:41:34
- 지휘: Claude Code (오케스트레이터 세션)

## 지시

[구현 과제] page_plan 에 남는 dangling photo_id 제거

## 문제 (내가 산출물로 직접 확인한 사실)

`generated/attached/fan-set-usage-scene/result_summary.json` 기준:

```
page_plan 의 scale_reference : photo_id = "scale"
photos 배열                  : hero, packshot, detail, lifestyle,
                               detail-02 ~ detail-05   ← scale 없음
```

렌더 시점에는 `hero` 로 대체되고 경고 로그가 남는다.

```
photo_id 'scale' requested by scale_reference block is unavailable;
using default photo_id 'hero'
```

정본인 `react_document` 에는 이 참조가 남지 않는다(대체가 그 전에 일어난다).
하지만 하위 호환용 `page_plan` 에는 `"scale"` 이 그대로 남아, `page_plan` 의
`photo_id` 로 `photos` 배열을 찾는 구현은 깨진다.

## 할 일

BE·FE 로 내려가는 `page_plan` 의 `photo_id` 가 **실제로 배정된 사진**을 가리키게
한다. 즉 렌더에서 일어나는 대체 결과가 `page_plan` 에도 반영돼야 한다.

먼저 대체가 어디서 일어나는지 코드를 따라가서 확인하라
(`react_document_builder.py` 의 `_photo_ids` / `_DEFAULT_PHOTO_BY_BLOCK` 근처와
HTML 렌더러 경로를 보라). 그 다음, 같은 해소 결과가 응답 DTO 의 `page_plan` 에도
적용되도록 고쳐라.

**사진을 새로 만들지 마라.** `scale` 컷을 생성하는 것은 별도 안건이다.
이번 과제는 참조 정합성만 맞추는 것이다.

## 하지 말 것

- `assets/references/detail-page-layouts.json` 카탈로그를 건드리지 마라.
  `scale_reference` 원형을 카탈로그에서 빼는 식의 해결은 금지다.
- 경고 로그를 없애지 마라. 대체가 일어났다는 사실은 계속 남아야 한다.
- 다른 블록의 사진 배정 규칙을 바꾸지 마라.

## 테스트

`photos` 에 없는 `photo_id` 를 요청하는 블록이 있을 때, 응답 `page_plan` 의
`photo_id` 가 실제 존재하는 사진을 가리키는지 검증하는 테스트를 추가하라.
단언을 약하게 만들지 마라.

`.venv/bin/python -m pytest` 전체를 돌리고 숫자를 그대로 보고하라.
현재 기준은 394 passed 다.

### 1. 변경 파일

1. **`src/detail_page_ai/react_document_builder.py`**
   - `resolve_page_block_photos(block, available_photo_ids)` 및 `resolve_page_plan_photos(page_plan, available_photo_ids)` 구현 및 `__all__`에 export.
   - `_apply_resolved_photo_ids`: 블록 타입(단일 이미지 블록 vs 갤러리)에 맞추어 해소된 photo_id/photo_ids를 `PageBlockDto`에 반영.
   - `build_react_document_from_draft`: `available_photo_ids`가 전달되면 `draft.page_plan`의 블록들을 해소하여 `draft.page_plan[:] = resolved_blocks`로 갱신.
   - `_build_block`, `_media_group`, `_image_figures`에 `resolved_photo_ids` 전달 경로를 추가하여, 블록당 대체 판정과 경고 로그(`photo_id 'scale' requested by scale_reference block is unavailable; using default photo_id 'hero'`)가 중복 없이 정확히 1회만 발생하도록 보장.

2. **`src/detail_page_ai/pipeline.py`**
   - `DetailPagePipeline.run`에서 `build_react_document_from_draft(approved_draft, available_photo_ids=...)` 호출 직후 `profile = profile.model_copy(update={"page_plan": list(approved_draft.page_plan)})`로 갱신.
   - 이를 통해 BE 저장 요청(`be_request.product.page_plan`)과 FE 반환 결과(`fe_result.product.page_plan`)에 dangling `photo_id` 없이 실제 존재하는 사진 ID(예: `scale` -> `hero`)가 전달되도록 정합성 확보.

3. **`src/detail_page_ai/dto.py`**
   - `AiBeProductPersistRequest.from_profile`: `generated_photos`가 전달되고 `profile.page_plan`이 존재할 때 `resolve_page_plan_photos`를 수행하도록 방어 가드 추가 (단독 호출 시에도 dangling photo_id 유입 차단).

4. **`src/detail_page_ai/__init__.py`**

   - `test_resolve_page_plan_photos_filters_gallery_unavailable_photos`: `gallery`에서 없는 `photo_id` 필터링 검증.
   - `test_resolve_page_plan_photos_clears_photo_when_default_also_unavailable`: 요청 사진 및 기본 사진 모두 없을 때 `photo_id=None` 처리 및 경고 로그 검증.
