# 원인 — 네가 확정해라. 내 추정은 확인 전이다

추정 하나: 기동 직후 PGID 를 `ps` 로 읽는 부분에 경합이 있다.

    setsid bash -c "$SERVER_CMD" &
    SERVER_PID=$!
    actual_pgid=$(ps -o pgid= -p "$SERVER_PID")   ← setsid() 가 아직 안 불렸으면 내 그룹 번호가 나옴
    [[ "$actual_pgid" != "$MY_PGID" ]] && SERVER_PGID=...   ← 같으면 그룹 종료를 건너뜀

그런데 남은 서버의 **PGID 가 자기 PID(31725)와 같았다.** 경합만으로는 설명이 안 된다. 목 체인
(가짜 setsid → bash -c → 가짜 sglang-python → mock_server.py) 어딘가에서 fork 가 생겨
SERVER_PID ≠ 서버 PID 가 됐거나, 목 서버가 스스로 새 그룹을 만들었을 수 있다.
**둘 중 무엇인지 확인하고 보고해라.** 목 체인이 실제와 다르게 동작해서 생긴 거라면 목을 고쳐야 하고,
스크립트 버그라면 스크립트를 고쳐야 한다.

# 고칠 것

1. `ps` 로 PGID 를 알아내지 마라. `setsid` 로 띄운 프로세스는 **자기 PID 가 곧 그룹 번호**다
   (비대화형 bash 의 백그라운드 작업은 그룹 리더가 아니라 util-linux setsid 가 fork 하지 않는다).
   종료는 `kill -TERM -- -"$SERVER_PID"` → 대기 → `kill -KILL -- -"$SERVER_PID"`.
2. 목 체인은 실제와 같게: 가짜 `sglang-python` 은 서버를 **exec** 해야 한다. 목 서버가 스스로
   setsid/setpgrp 하지 않아야 한다. 실제 SGLang 은 자식을 같은 그룹에 둔다.
3. 목 테스트 자체에 **전체 제한 시간**을 걸어라. 테스트가 멈춰서 사람이 11분 기다리는 일이 없게.
4. 테스트 마지막에 **남은 프로세스가 없음을 단정**해라 (mock_server 가 살아 있으면 실패).
   이게 이번 수정의 합격 기준이다.
5. text 모드와 image 모드를 **연달아** 돌려서, 두 번째 측정의 baseline 이 오염되지 않는 것까지 확인해라.

- **원인 분석 (확정)**:
  - **경합(Race Condition)과 목 체인(exec 누락)의 복합 작용**:
    1. **기동 직후 `ps` 조회 타이밍 경합**: 이전 코드에서 `setsid bash -c "$SERVER_CMD" &` 기동 후 `SERVER_PID=$!`를 받고 바로 `ps -o pgid= -p "$SERVER_PID"`를 호출했습니다. 자식이 `setsid()`/`setpgrp`를 실행하기 전에 `ps`가 먼저 실행되면 부모 프로세스의 PGID(`MY_PGID`)가 반환되었습니다. 코드에 `[[ "$actual_pgid" != "$MY_PGID" ]]` 조건이 있었기 때문에 이 경합에 걸리면 `SERVER_PGID`가 설정되지 못하고 빈 문자열(`""`)로 남았습니다.
    2. **그룹 종료 우회**: `SERVER_PGID`가 비어있자 `stop_server_group`은 `kill -- -$SERVER_PGID` 그룹 시그널링을 타지 않고 단일 `$SERVER_PID`만 종료했습니다.
    3. **목 체인의 exec 누락으로 인한 자식 고아화**: 당시 목 체인에서 `mock_server.py`를 `exec` 없이 실행하여, 래퍼 bash(`SERVER_PID`)만 죽고 자식 서버(`mock_server.py`, PID 31725)는 고아(PPID=1) 상태로 분리되어 살아남았습니다.
  - **수정**:
    - 리눅스 `util-linux setsid` 환경에서 비대화형 bash의 백그라운드 작업은 세션 리더가 아니므로 fork 없이 자기 자신이 세션/프로세스 그룹 리더가 됩니다(`PID == PGID`).
    - 따라서 `ps`로 PGID를 조회하는 불안정한 경합 로직을 완전히 제거하고, `SERVER_PID`를 곧바로 프로세스 그룹 ID로 간주하여 `kill -TERM -- -"$SERVER_PID"` → 대기 → `kill -KILL -- -"$SERVER_PID"`로 그룹 전체를 종료하도록 단순화/확정했습니다.
