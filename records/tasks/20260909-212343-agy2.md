## 지시

## 역할

너는 감시 담당이다. 코드를 고치는 워커가 아니라, 다른 워커들이 작업하는 동안 저장소가
망가지지 않는지 **반복해서 점검하고 기록**하는 일을 한다.

## 반복할 점검 (1회 = 1사이클)

아래 네 가지를 순서대로 실행한다.

1. **테스트 회귀**
   `.venv/bin/python -m pytest -q`
   통과 개수를 기록한다. 직전 사이클보다 개수가 줄거나 실패가 생기면 회귀다.

2. **컷아웃 보존율**
   `.venv/bin/python scripts/check_cutout_fidelity.py --pilot-dir generated/evaluation/pilot-20260909-191344`
   종료 코드와 요약 줄(OK/부분 손실/심각 손실 건수)을 기록한다.

3. **작업 범위 이탈**
   `git status --short`
   현재 워커들에게 허용된 수정 범위는 다음뿐이다:
   - codex: `src/detail_page_ai/source_photos.py`, `tests/test_source_photos.py`
   - agy(ttys003): `docs/evaluation/` 아래 새 문서
   이 범위 **밖의 파일이 새로 변경되거나 삭제되었으면 경고**로 기록한다.
   특히 `data/` 와 `generated/` 아래 파일이 삭제되면 즉시 눈에 띄게 표시하라. 평가 데이터다.

4. **워커 완료 여부**
   `.orchestration/tasks/` 의 각 `.md` 파일에 `## 결과` 섹션이 있는지 확인한다.
   있으면 그 워커는 작업을 마친 것이다. 파일명과 완료 여부만 기록한다.

## 기록 방법

각 사이클 결과를 `.orchestration/watch/status.md` 에 **덧붙인다**(append, 덮어쓰지 마라).
형식은 다음과 같이 짧게:

```
## 사이클 N — 2026-09-09 21:40
- pytest: 241 passed
- cutout: exit 1 (OK 4 / 부분 1 / 심각 1)
- 범위 이탈: 없음
- 완료된 브리프: 20260909-201225-codex.md
```

**직전 사이클과 달라진 것이 있으면** 그 줄 앞에 `[변화]` 를 붙이고, 회귀나 범위 이탈이면
`[경고]` 를 붙여라. 아무 변화가 없으면 그대로 짧게 기록한다.

## 루프 방식

한 사이클을 마치면 `sleep 300` 으로 5분 기다린 뒤 다음 사이클을 시작한다.
**총 12 사이클(약 1시간) 수행하고 멈춘다.** 그 뒤 브리프 파일 하단에 `## 결과` 로
전체 요약(회귀 발생 여부, 경고 목록)을 적어라.
