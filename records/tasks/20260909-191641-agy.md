## 근거 (반드시 먼저 읽을 것)

`docs/evaluation/metrics-definition.md` 의 "3. 사람 검수와 통계" 절이 기준이다.

- 축은 네 가지: 사실성, 명료성, 상품성, 시각 품질. 각 1~5점.
- 1 = 사용 불가, 3 = 상당한 수정 필요, 5 = 수정 없이 사용 가능. 평균 목표 4.0 이상.
- 검수자 2인의 독립 점수, 의견 차이, 합의 결과를 모두 보존한다. 미검수는 정답으로 쓰지 않는다.
- 상품별 macro 평균과 전체 micro 평균, 표본 수, 비율의 95% Wilson 구간을 함께 보고한다.

가이드 문서에는 각 축의 1점/3점/5점이 **이 프로젝트 산출물에서 구체적으로 무엇을 뜻하는지**
판별 가능하게 써라. 특히 사실성은 "원본 이미지에서 실제로 보이는 근거가 있는가" 와
"입력에 없던 가격·배송·관리법을 지어냈는가" 로 갈린다. 그 판정 항목은
`data/evaluation/cma_real_v1/analysis_60.jsonl` 각 case 의 `checks` 배열에 있다
(schema_valid, visible_features_grounded, no_invented_price_shipping_care,
source_facts_not_claimed_as_visually_observed).

## 스크립트 요구사항

- 입력: 파일럿 실행 디렉터리 경로 (`--pilot-dir`). 그 안의 `run_index.json` 을 읽는다.
- 출력: 같은 디렉터리에 `review_sheet.csv`.
- 열: case_id, category, asset_id, 입력 이미지 경로, 산출물 경로, 실행 성공 여부,
  검수자 A의 사실성·명료성·상품성·시각품질 4열, 검수자 A 코멘트,
  검수자 B의 같은 4열, 검수자 B 코멘트, 합의 점수 4열, 합의 메모.
- **점수 열은 반드시 빈 칸으로 생성한다.** 예시 점수나 자동 채점을 절대 넣지 마라.
- 실행 실패한 case 도 행으로 포함하되 실패 표시와 에러 메시지를 남긴다. 조용히 빼지 마라.
- CSV 는 UTF-8 BOM(`utf-8-sig`)으로 써서 엑셀에서 한글이 깨지지 않게 한다.
