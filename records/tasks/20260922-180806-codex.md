## 할 일 4가지

### 1. `docker-validate` 와 `publish` 두 job 의 `runs-on` 교체

**테스트 job(`test`)과 챗봇 API 는 기존 GitHub 러너를 유지한다.**
상세페이지와 챗봇 LLM 만 CodeBuild 로 간다.

인프라팀이 준 값 그대로 쓴다.

```yaml
runs-on: ${{ matrix.service == 'chatbot-api' && 'ubuntu-24.04' || format('codebuild-jangin-genai-runner-{0}-{1}', github.run_id, github.run_attempt) }}
```

현재 `runs-on: ubuntu-24.04` 는 26행(test), 102행(docker-validate), 175행(publish)
세 곳에 있다. **102행과 175행만 바꾼다. 26행은 그대로 둔다.**

### 2. ECR 저장소 이름 변경

`publish` job 의 matrix `repository` 값을 바꾼다.

| 서비스 | 현재 | **변경 후** |
| --- | --- | --- |
| 상세페이지 | `jangin-ai/sglang` | **`jangin-ai/page-generation`** |
| 챗봇 API | `jangin-ai/ollama` | **`jangin-ai/chatbot-api`** |
| 챗봇 LLM | `jangin-ai/chatbot-llm` | 그대로 |

`matrix.service` 이름(`page-generation`, `chatbot-api`, `chatbot-llm`)은 유지해도 된다.

### 3. 용량 부족 시 "건너뛰고 성공" 을 "실패" 로 바꾼다

`docker-validate` job 의 `Check PR build capacity` 스텝(약 138~159행)이 지금은
디스크가 모자라면 경고만 남기고 `exit 0` 으로 통과시킨다. 인프라팀 요청은
**실패 처리**다.

- `full_build=false` 분기와 그에 딸린 조건부 빌드 스킵을 없앤다
- 디스크가 모자라면 `::error::` 와 `exit 1` 로 실패시킨다
- `publish` job 쪽 용량 점검은 이미 실패 처리이므로 그대로 둔다

CodeBuild 러너로 가면 용량이 충분하므로 이 분기는 실질적으로 안전망이다.

### 4. 유지할 것 — 건드리지 마라

- OIDC `role-to-assume` 와 `aws-actions/configure-aws-credentials`
- 커밋 SHA 태그, `latest` 금지, IMMUTABLE 처리
- `linux/amd64` 플랫폼
- digest 출력 스텝
- 기존 SHA 충돌 시 재사용 로직(`Check immutable source-SHA tag`)
- `test` job 전체
