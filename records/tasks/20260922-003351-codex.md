## 2부 — 운영 가이드

`docs/operations/` 의 문서들과 `deploy/` 를 읽고 **운영자가 따라 할 수 있게** 쓴다.

1. **배포 형상** — EKS 단일 컨테이너 구조, 세 프로세스(FastAPI PID 1 + SGLang 2개),
   포트 8000/30000/30001. `eks-workload-spec.md` 1-1 절 기준.
2. **자원 요구** — CPU·Memory·GPU. `eks-workload-spec.md` 1-4 절의 **실측·추정 구분을
   그대로 옮겨라.** 무엇이 실측이고 무엇이 추정인지 흐리지 마라.
3. **모델 준비** — S3 → PVC 동기화 대상 3종과 배치 경로. 누끼 모델 파일명 규칙
   (`birefnet-general.onnx`) 주의사항 포함.
4. **환경변수** — Secret 과 ConfigMap 구분. `src/detail_page_ai/config.py` 에서
   실제 alias 를 확인해 표로.
5. **헬스체크** — `/health` 와 `/health/ready` 차이, liveness 로 ready 를 쓰면 안 되는 이유.
6. **기동 순서와 실패 모드** — 모델 동기화 전에 파드가 뜨면 어떻게 되는지
   (`deploy/sglang/entrypoint.sh` 의 오류 메시지 확인).
7. **로그에서 봐야 할 것** — 최소한 누끼 프로바이더 선택 로그
   (`rembg ONNX Runtime providers: ...`)를 넣어라. GPU 를 실제로 탔는지 확인하는 유일한 방법이다.
8. **알려진 운영 제약** — 예: PVC 가 RWO 라 단일 파드, 렌더 메모리 실측 12.9 GiB 등.
