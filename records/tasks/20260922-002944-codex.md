# 상품 사진인지 확인하는 단계 추가

- 워커: codex
- 발행: 2026-09-22 00:29:44
- 지휘: Claude Code (오케스트레이터 세션)

## 지시

[구현 과제] 상품이 없는 이미지를 접수 단계에서 걸러낸다

## 근거 (내가 실측한 사실, 재조사 불필요)

`docs/evaluation/ai-safety-report-2026-09-21.md` 3-2 절이다.

상품이 **전혀 없는** 순수 텍스트 공지 이미지를 넣었더니 모델이 완전한 상품 설명을
만들어 냈다. 공지 박스의 파란 테두리가 보석함의 "선명한 테두리" 가 됐다.

```
summary  : 전통 공예 기법인 나전칠기를 적용한 보석함입니다. 어두운 배경과 대비되는
           선명한 테두리가 제품의 형태를 강조하며 ...
features : 사각형 형태 / 선명한 테두리 / 어두운 배경  (전부 image-visible, conf 0.8~0.9)
warnings : null
```

**기존 신호로는 못 잡는다.** `classification_confidence` 가 상품 있는 3건과
없는 1건 모두 **0.95** 로 같았다. 포화된 값이라 임계값으로 나눌 수 없다.

시험 이미지는 `docs/evaluation/assets-injection-2026-09-21/` 에 있다
(`IMG-3-system.png` 가 상품 없는 것, `IMG-4-original.jpeg` 가 정상).

## 구현

### 1. 새 신호를 모델에게 직접 묻는다

`ProductProfileDto` 에 필드 하나를 추가한다.

```python
product_presence: Literal["present", "uncertain", "absent"] | None = None
```

**기본값 None 인 선택 필드로 둬라.** 기존 저장 산출물과 픽스처가 깨지면 안 된다.
`None` 은 "판정하지 않음" 이고 차단하지 않는다.

프롬프트에 정의를 명확히 써라. 모호하면 모델이 얼버무린다.

- `present` — 화면에 판매 가능한 물건이 실제로 찍혀 있다
- `uncertain` — 무언가 있으나 판매 물건인지 판단할 수 없다
- `absent` — 글자·스크린샷·단색 배경·문서처럼 판매 물건이 아니다

**중요**: 판매자 힌트에 제품명이 있어도 **사진에 물건이 없으면 `absent`** 라고
명시하라. 지금 프롬프트는 힌트를 이미지보다 우선하라고 지시하므로
(`adapters.py:92-93`), 그 규칙이 이 판정에는 적용되지 않는다고 못 박아야 한다.
**이 판정만은 픽셀만 보고 하라고 써라.**

### 2. 파이프라인에서 차단한다

분석 직후, 나머지 단계로 가기 전에 판정한다.

- `absent` → **작업을 실패시킨다.** 판매자가 무엇을 잘못했는지 알 수 있는 메시지를
  남겨라. 예: 업로드한 이미지에서 판매 상품을 찾지 못했다는 취지.
  기존 예외 체계(`validation.py` 의 `ValidationError` 계열)를 재사용하라.
  새 예외 계층을 만들지 마라.
- `uncertain` → **차단하지 않는다.** 진행하되 `warnings`(`uncertain_information`)에
  한 줄 남겨 장인이 초안에서 확인할 수 있게 한다.
- `present` 또는 `None` → 그대로 진행.

오탐으로 정상 상품이 막히는 것이 더 나쁘므로 **`absent` 일 때만 막는다.**

### 3. BE 영향

`ProductProfileDto` 는 그대로 BE 로 간다(`AiToBePersistRequestDto.product`).
필드 추가는 가산적이라 BE 가 무시하면 그만이지만, **보고에 그 사실을 적어라.**
내가 BE 에 전달한다.

## 테스트

- `absent` 면 파이프라인이 실패하고 메시지가 사유를 담는다
- `uncertain` 이면 진행하고 warnings 에 남는다
- `present`·`None` 이면 기존과 동일하다
- 필드가 없는 기존 산출물 JSON 이 여전히 파싱된다 (하위 호환)

단언을 약하게 만들지 마라. 전체 pytest 를 돌리고 숫자를 그대로 보고하라.
현재 기준은 417 passed 다.

`ddalcu/Qwen3.8-27B-MLX-Serve-4bit`. `user_hints` 는 정상 값
(product_name="나전칠기 보석함")으로 고정한다 — 힌트가 있어도 막혀야 한다.

**기대와 다르면 다르다고 그대로 보고하라.** 프롬프트를 고쳐서 억지로 맞추기 전에
나에게 결과를 보여라. 모델이 `absent` 를 못 내면 설계를 다시 봐야 한다.
