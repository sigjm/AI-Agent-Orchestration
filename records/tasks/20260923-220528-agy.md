## 지시

`scripts/runtime/measure_vram.sh` 를 검수했다. 요청 형태(`/v1/images/edits`, 4 steps, 1024x1024)는
프로덕션 `src/local_detail_page_ai/clients.py` 와 맞다. 좋다. 다만 **L40S 는 Stage 워크로드를 내려야
쓸 수 있는 짧은 시간**이라, 그 시간을 날리는 결함부터 고쳐야 한다.

## 1. 기동 대기 타임아웃 300초는 너무 짧다 (반드시)

Stage 로그에서 텍스트 서버는 **가중치 로드만 252.71초** 걸렸다. 그 뒤 CUDA 그래프 캡처가 더 붙는다.
300초면 정상 기동을 실패로 판정할 가능성이 크다. 기본값을 **1800** 으로 올려라
(entrypoint 의 `TEXT_READY_TIMEOUT` 기본값과 같다).

## 2. 기준값(baseline) 검사가 없다 (반드시)

Stage 상세페이지 파드가 아직 GPU 를 쥐고 있거나, 앞 측정의 프로세스가 남아 있으면
**오염된 숫자가 정상처럼 나온다.** 시작 시 baseline 이 임계값(기본 1024 MiB, env 로 조정 가능)을 넘으면
`nvidia-smi --query-compute-apps=pid,used_memory --format=csv` 결과를 보여주고 **실패로 끝내라.**

## 3. `pkill -P` 는 직계 자식만 죽인다 (반드시)

`eval "$SERVER_CMD" &` 아래에서 SGLang 은 scheduler·detokenizer 를 **손자 프로세스**로 띄운다.
직계 자식만 죽이면 손자가 VRAM 을 쥔 채 남아 **다음 모드(text → image) 측정이 오염된다.**
`setsid` 로 새 프로세스 그룹에서 띄우고 `kill -- -<PGID>` 로 그룹 전체를 종료해라 (TERM → 대기 → KILL).
종료 후 VRAM 이 baseline 근처로 돌아왔는지 확인하고, 안 돌아오면 경고를 남겨라.

## 4. 요청 구간 샘플이 없으면 숫자를 내지 마라

지금은 요청 구간 샘플이 비면 CSV 전체 최댓값으로, 그것도 없으면 `loaded` 값으로 대체한다.
전체 최댓값에는 **로딩 구간이 섞여** 요청 peak 로 잘못 읽힌다. 요청 구간 샘플이 없으면 **실패로 끝내라.**

## 5. `curl`·`base64`·`setsid` 가 없으면 즉시 실패

지금은 curl 이 없으면 `000` 으로 타임아웃까지 헛돈다. 시작 시 `command -v` 로 확인하고 바로 실패해라.
