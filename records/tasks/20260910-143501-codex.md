# 교차검증 — 비어 있는 variant 4종 CSS 구현

## 지시

## 이 작업의 성격

**교차검증이다.** 다른 워커 한 명이 같은 브리프로 독립 작업 중이다.
상대의 결과 파일이나 `.orchestration/tasks/` 의 다른 브리프를 열지 마라.
상대와 결론을 맞추려 하지 말고, 네 판단으로 만들어라.

## 문제

상세페이지의 시각적 다양성이 부족하다. 원인을 추적한 결과 **DTO 에 선언된 variant 8종 중
절반이 CSS 규칙이 0개**다.

| variant | DTO | `web/detail_page.css` 규칙 수 |
|---|---|---|
| paper | 있음 | 5 |
| light | 있음 | 5 |
| dark | 있음 | 9 |
| full-bleed | 있음 | 9 |
| **sand** | 있음 | **0** |
| **image-left** | 있음 | **0** |
| **image-right** | 있음 | **0** |
| **compact** | 있음 | **0** |

모델이 `image-left` 를 내도 화면은 안 바뀐다. 좌우 반전, 여백 축소, 색면이 전부 죽어 있다.

## 작업

`web/detail_page.css` 에 비어 있는 네 variant 의 규칙을 구현한다.

- `.block--sand` — 따뜻한 색면 배경. 기존 `paper`/`light`/`dark` 와 **명확히 구별되는 톤**이어야
  한다. 프로젝트 색 체계는 `src/detail_page_ai/reference_guide.py` 의 `REFERENCE_GUIDE_COLORS`
  에 있다. 거기 정의된 값을 쓰고 새 색을 지어내지 마라.
- `.block--image-left` / `.block--image-right` — 이미지와 텍스트의 좌우 배치를 뒤집는다.
  기존 `detail_split` 계열 레이아웃이 어떻게 조판되는지 먼저 읽고, 그 구조 위에서 방향만
  바꾸는 최소 규칙으로 만들어라.
- `.block--compact` — 여백과 타이포 스케일을 줄여 밀도 높은 섹션을 만든다.
  섹션이 연속될 때 리듬 변화를 주는 용도다.

**렌더러가 variant 를 어떤 클래스로 내보내는지 먼저 확인하라** (`src/detail_page_ai/html_renderer.py`).
클래스 이름이 `block--{variant}` 가 맞는지 코드로 확인하고 시작하라. 추측하지 마라.

## 지켜야 할 것

- **기존 4종(`paper`·`light`·`dark`·`full-bleed`) 규칙을 바꾸지 마라.** 추가만 한다.
  기존 페이지 렌더가 달라지면 회귀다.
- 반응형을 깨뜨리지 마라. 캔버스 폭은 774px 고정이고 Playwright 로 PNG 를 렌더한다.
- `reference_guide.py` 의 타이포 스케일(hero 40/700/1.25, 섹션 제목 30/700/1.35,
  카드 제목 19/600/1.4, 본문 16/400/1.7, 라벨 13/500/1.5)과 어긋나지 않게 하라.
- 다크 모드 대응은 불필요하다. 이 CSS 는 상세페이지 PNG 렌더용이지 뷰어용이 아니다.

## 검증

보이는지 확인할 수 있는 최소 확인 방법**을 결과 보고에 적어라. 스크립트를 새로 만들지는 마라
(다른 워커가 같은 파일을 만들 수 있다). 어떻게 확인했는지 서술하면 된다.

## 결과

### 변경 파일

- `web/variants-codex.css`만 추가했습니다. `detail_page.css`와 다른 기존 파일은 수정하지 않았습니다.
- `.block--sand`: `yellow_500`과 `jade_blue_50` CSS 변수만 `color-mix`해 저채도 따뜻한 색면을 만들고, closing 조합은 중앙 정렬·넉넉한 마무리 여백으로 처리했습니다. 새 임의 색상은 추가하지 않았습니다.
- `.block--image-left` / `.block--image-right`: `detail_split`의 실제 media-first DOM 및 `image-right`의 `split-section--reverse` 보조 클래스를 기준으로, 이미지 42%·카피 58%의 비대칭 좌우 배치를 명시했습니다. `image-left + dark`에는 레퍼런스 맥락에 맞춰 넓은 다크 카피 면과 세리프 제목(30/700/1.35)을 추가했습니다.
- `.block--compact`: `info_table`의 실제 `table > tbody > tr` 구조를 전체 폭 2×2 사양 카드로 조판했습니다. 라벨은 13/500/1.5, 값은 16/400/1.7, 섹션 제목은 30/700/1.35이며 640px 이하에서는 단일 열로 전환됩니다.

### 검증 방법

- `scripts/browser/test_detail_page_layout.mjs`의 Playwright 방식에 따라, 기존 `detail_page.css` 뒤에 이 파일을 일회성으로 로드한 774px 임시 페이지를 PNG로 렌더하고 눈으로 확인했습니다. image-left/image-right의 좌우 위치와 42:58 비율, sand의 색면·중앙 정렬, compact의 전체 폭 2×2 배치를 확인했습니다.
- 같은 Playwright 확인에서 계산 스타일과 기하 정보를 검증했습니다. compact `tbody`가 table 전체 폭을 차지하는지, 제목/라벨/값이 각각 30px/13px/16px인지, 600px 미디어 조건에서 split·compact가 단일 열이 되는지를 확인했습니다.
- `.venv/bin/python -m pytest -q --deselect tests/test_validation.py::test_editorial_plan_fills_missing_recommendation_without_replacing_ai_order` → `296 passed, 1 deselected`.
- `web/variants-codex.css`의 후행 공백은 없음을 확인했습니다.

### 미해결 이슈

- 전체 `pytest -q`는 이번 CSS와 무관한 `tests/test_validation.py::test_editorial_plan_fills_missing_recommendation_without_replacing_ai_order` 1건에서 실패했습니다. 현재 다른 변경의 `validation.py`가 기본 `paper` variant를 보존하지만 이 테스트는 `detail_split`을 `dark`로 강제할 것을 기대합니다. 이 브리프에서 `src/`·`tests/`는 읽기 전용이므로 수정하지 않았습니다.
- 작업 트리에 다른 워커의 `assets/references/detail-page-layouts.json`, `validation.py`, 테스트, `web/variants-agy.css` 변경이 있습니다. 전역 `git diff --check`의 EOF 공백 경고도 다른 워커의 테스트 파일에서 발생하며, 제 CSS 파일에는 해당 문제가 없습니다.
- 현 `detail_split` 마크업에는 이미지 컨테이너가 하나이고 번호 매김용 항목 구조도 없습니다. 따라서 레퍼런스의 “접사 이미지 두 장”과 “번호 설명 두 개”는 이미지·콘텐츠를 임의 복제하지 않았습니다. 이 별도 CSS 파일은 통합 시 `detail_page.css` 뒤에 로드해야 하며, 렌더러/HTML 수정은 지시대로 수행하지 않았습니다.
