## 노트북 구성 (셀 순서)
0. 맨 위 마크다운: 목적, 필요한 런타임(**GPU L4 권장 — L40S 와 같은 Ada 세대**, A100 이면 동시 기동까지), 예상 다운로드(텍스트 약 21 GB, 이미지 약 10.2 GiB), 실행 방법, 결과 파일 위치.
1. 결과 기록기: `/content/sglang_smoke/results.json` 과 `results.md` 에 단계별 `{단계, 상태(PASS/FAIL/SKIP), 시작·종료 시각, 소요 초, 핵심 수치, 오류 메시지 앞부분}` 을 **단계가 끝날 때마다** 덧붙여 저장. 중간에 런타임이 끊겨도 기록이 남게.
2. 환경 기록: GPU 이름, 총 VRAM(GiB), 드라이버 버전, `nvidia-smi` 가 보고하는 CUDA 버전, compute capability, Python 버전, 디스크 여유, 시스템 RAM.
3. 판정 규칙을 코드로:
   - compute capability < 8.0 (예: T4) → 이후 단계 SKIP, 사유 기록.
   - VRAM < 20 GiB → 텍스트 서버 SKIP.
   - 텍스트 단독 `--mem-fraction-static` = `min(0.90, (19.6+3.0)/총VRAM)` 로 계산하고, L40S 운영값(0.50=22.35 GiB)과 다르다는 점을 기록.
   - 총 VRAM ≥ 37 GiB 면 **동시 기동 단계** 수행: 텍스트 비율은 L40S 와 같은 절대량 22.35 GiB 가 되도록 `22.35/총VRAM`.
4. 설치: 고정 버전 설치, 소요 시간, `import sglang, torch, bitsandbytes` 성공 여부와 버전, `torch.cuda.is_available()`.
5. 테스트 입력 이미지: 업로드 없이 PIL 로 1024×1024 합성 상품 이미지(단색 배경 위 도형)를 만들어 저장. 원하면 관리자가 자기 사진을 올릴 수 있는 선택 셀을 따로.
6. **이미지 서버 단독**: 기동(서버 로그를 파일로), `GET /v1/models` 가 200 이 될 때까지 대기(제한 시간 넉넉히, 기동 소요 기록), 로그에서 bitsandbytes/4bit 로딩·오프로드 관련 줄을 찾아 기록, `nvidia-smi` 사용 메모리. 생성 1회(1024×1024, `num_inference_steps` 4), 편집 1회(합성 이미지 입력) — 각각 소요 초, 응답 이미지 크기, 결과 PNG 저장, 생성 중 최대 VRAM(백그라운드로 `nvidia-smi --query-gpu=memory.used` 폴링). 종료 후 GPU 메모리 해제 확인.
7. **텍스트 서버 단독**: 같은 방식. 채팅 요청 1회(합성 이미지 + "이 이미지의 색과 모양을 JSON 으로" 류 짧은 프롬프트, `response_format json_object`), 응답이 JSON 으로 파싱되는지, 소요 초, 최대 VRAM.
8. **동시 기동**(조건 충족 시): 두 서버를 함께 띄워 각각 1회씩 요청, 합계 VRAM 과 성공 여부. L40S 조건을 가장 가깝게 재현하는 단계임을 기록.
9. 정리·다운로드: 서버 프로세스 종료, `/content/sglang_smoke` 를 zip 으로 묶어 `google.colab.files.download` (Colab 이 아닐 때는 건너뜀).
