# entrypoint 순서 테스트가 CI 에서 경합으로 실패

- 워커: codex
- 발행: 2026-09-23 22:39:30

## 지시

# 무슨 일이 있었나

네가 만든 `test_api_starts_before_image_and_image_waits_for_text` 가 GenAI CI(Linux, 로컬보다 약 2.8배 느림)에서 실패했다.
로컬에선 통과한다. **entrypoint 는 정상이고 테스트 하네스가 경합한다.**

    AssertionError: assert 'VRAM image-ready: 123 MiB, 456 MiB' in '...
      FastAPI service exited while waiting for SGLang image server
      SGLang image server did not become ready; stopping container'

`_run_fake_runtime` 이 이렇게 돼 있다.

    if "image-start" in events: break      # 이미지가 '시작'되자마자 대기 종료
    process.terminate()                    # 가짜 FastAPI 를 곧바로 죽임
    ...
    assert "VRAM image-ready: ..." in stderr   # 그런데 '준비' 로그를 단정

감시 루프는 1초 간격으로 이미지 준비를 확인하고, 준비를 본 뒤에야 VRAM 을 찍는다. 로컬에선 그 확인이
terminate 보다 먼저 와서 통과했고, 느린 CI 에선 terminate 가 먼저 와서 entrypoint 가 **올바르게**
"FastAPI 가 죽었으니 컨테이너 중지" 로 갔다.

# 고칠 것 — `tests/test_sglang_entrypoint.py` 만

1. 가짜 `nvidia-smi` 가 호출될 때 `$EVENTS_FILE` 에 `vram` 을 한 줄 남기게 해라
2. 하네스는 **`vram` 이 2번(텍스트 준비·이미지 준비) 기록될 때까지** 기다린 뒤 terminate 해라.
   시간 대기가 아니라 이벤트 대기다
3. 전체 deadline 5초는 느린 러너에서 빠듯하다. 30초로 늘려라 (정상이면 바로 끝나니 실패할 때만 의미가 있다)
4. `text_fails_before_ready` 경로는 지금 동작 그대로

# 하지 말 것

- **단정을 빼거나 약화하지 마라.** `VRAM image-ready` 단정은 그대로 둔다. 기다리는 조건을 맞추는 것이다
- `deploy/sglang/entrypoint.sh` 수정 금지 — 문제는 거기 없다
- 커밋 금지

# 검증 (결과에 붙여라)

- 전체 `pytest -q`
- 이 테스트를 **20번 반복**해서 전부 통과
- **느린 러너 재현**: 가짜 `sglang-python -c` 확인에 `sleep 1` 을 넣은 상태로 한 번 돌려 통과하는지
  (확인 후 그 sleep 은 되돌려라). 수정 전 코드라면 이 조건에서 실패해야 한다 — 가능하면 그것도 보여라

## 결과

- 변경 파일은 지시대로 `tests/test_sglang_entrypoint.py` 한 개뿐이다. `deploy/sglang/entrypoint.sh`는 수정하지 않았고 커밋도 만들지 않았다.
- fake `nvidia-smi`가 호출될 때 `$EVENTS_FILE`에 `vram` 이벤트를 기록하도록 했다. 정상 경로 하네스는 `image-start` 직후 종료하지 않고 `vram` 이벤트가 2번(텍스트 준비·이미지 준비) 기록될 때까지 기다린 뒤 terminate한다.
- 하네스 전체 deadline을 5초에서 30초로 늘렸다. fake probe가 1초씩 지연되는 실행도 수용하도록 테스트 전용 `TEXT_READY_TIMEOUT`을 2초에서 5초로 조정했다. `text_fails_before_ready` 경로의 즉시 종료 조건은 유지했다.
- 느린 러너 재현으로 fake `sglang-python -c`에 임시 `sleep 1`을 넣고 순서 테스트를 1회 실행했으며 `1 passed`로 통과했다. 확인 후 임시 sleep은 되돌렸다.
- 최종 상태의 순서 테스트를 20회 반복 실행해 20회 모두 통과했다.
- 전체 검증: `.venv/bin/python -m pytest -q` → `427 passed, 2 warnings in 20.14s`; `git diff --check` 통과.
- 미해결 이슈는 없다. 남은 2개 warning은 기존 FastAPI/Starlette의 `httpx`·`anyio` deprecation warning이다.
