## 지시

## 배경

상세페이지 서비스를 AWS EKS 에 올려 검증해야 하는데 **저장소에 `Dockerfile` 이 없다.**
인프라 팀이 베이스 이미지와 예상 크기를 물어온 상태다. 설계는
`docs/operations/aws-deployment.md` 에 정리해 두었으니 **먼저 그 문서 4절과 7절을 읽어라.**

이번 작업 범위는 **ai-service 컨테이너 하나**다. 추론 서버(vLLM/diffusers) 컨테이너는
CUDA 재포팅 결과가 나와야 정해지므로 이번에 만들지 않는다.

## 만들 것

- `Dockerfile`
- `.dockerignore`

## 요구사항

1. **베이스는 `python:3.13-slim`.** ai-service 자체는 GPU 를 쓰지 않는다. 모델 추론은 전부
   HTTP 로 별도 서버(`LOCAL_TEXT_URL`, `LOCAL_IMAGE_URL`)에 위임한다. CUDA 베이스를 쓰지 마라.

2. **Node.js + Playwright Chromium 이 필요하다.** 승인 후 최종 PNG 렌더가
   `src/detail_page_ai/html_renderer.py` 에서 `scripts/runtime/render_detail_page.mjs` 를
   subprocess 로 실행한다. `package.json` 의 의존성과 실행 스크립트를 확인하라.
   Chromium 을 빼면 렌더 단계가 실패하므로 반드시 포함한다.
   Playwright 브라우저 설치 경로가 런타임 사용자와 맞는지 확인하라 (설치는 root, 실행은
   비root 로 하면 브라우저를 못 찾는 실수가 흔하다).

3. **비root 사용자로 실행한다.** 상태 디렉터리 쓰기 권한을 그 사용자에게 준다.

4. **상태 경로를 볼륨 마운트 지점으로 만든다.** 기본값이 `.local/detail-page-ai/` 아래인데
   컨테이너에서는 부적절하다. `SQLITE_PATH` 와 `ASSET_STORE_DIR` 를 `/var/lib/detail-page-ai/`
   같은 경로로 두고 `VOLUME` 을 선언하라. **기본값을 코드에서 바꾸지 말고 ENV 로 지정하라.**

5. **레이어 순서를 캐시 효율에 맞춘다.** 의존성 설치가 소스 복사보다 앞에 와야 한다.
   `pyproject.toml` 과 `package.json` 을 먼저 복사해 설치한 뒤 소스를 복사하는 구성으로.

6. **`EXPOSE 8000`**, 진입점은 `serve-ai` (`pyproject.toml` 의 `[project.scripts]`).

7. **헬스체크**를 넣어라. 다만 이 서비스에는 전용 health 엔드포인트가 없다.
   있는 경로로 확인하거나, 없으면 넣지 말고 **"health 엔드포인트 신설이 필요하다"고
   결과 보고에 남겨라.** 없는 엔드포인트를 호출하는 헬스체크를 만들지 마라.

8. `.dockerignore` 로 `generated/`, `.local/`, `.venv/`, `node_modules/`, `data/`, `.git/`,
   `.orchestration/` 을 제외한다. 특히 `data/`(20MB)와 `generated/`(600MB 이상)가 빌드
   컨텍스트에 들어가면 안 된다.

## 검증

`docker build` 가 이 환경에서 가능한지 먼저 확인하라 (`docker info`). **가능하면 빌드해서
최종 이미지 크기를 재고 결과 보고에 적어라.** 불가능하면 빌드하지 말고 "빌드 미검증"이라고
명시하고, 예상 크기의 근거(베이스 이미지 + Chromium + 의존성)를 적어라.
**추측한 크기를 측정값처럼 적지 마라.**

## 결과

### 변경 파일

- `Dockerfile`
  - `python:3.13-slim` 기반의 CPU 전용 ai-service 이미지를 추가했다.
  - `nodejs`·`npm`과 `package-lock.json` 기반 `npm ci`, Playwright Chromium 및 시스템 의존성을 설치한다.
  - `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`를 사용해 root 설치 브라우저를 런타임 비root 사용자 `appuser`가 읽도록 소유권을 맞췄다.
  - `pyproject.toml`·`package.json`·`package-lock.json`을 소스보다 먼저 복사해 의존성 레이어 캐시를 보존한다.
  - `/var/lib/detail-page-ai`를 `VOLUME`으로 선언하고 `SQLITE_PATH`·`ASSET_STORE_DIR` 기본값을 해당 경로로 ENV 지정했다.
  - `EXPOSE 8000`, 비root `USER appuser`, `CMD ["serve-ai"]`를 설정했다.
  - 전용 health endpoint를 신설하지 않고 기존 `/api/v1/ai/detail-page-jobs/does-not-exist` 경로의 404 응답을 정상 상태로 확인하는 `HEALTHCHECK`를 추가했다.
- `.dockerignore`
  - `generated/`, `.local/`, `.venv/`, `node_modules/`, `data/`, `.git/`, `.orchestration/`과 Python·테스트 캐시를 제외했다.

### 검증 방법

- `docs/operations/aws-deployment.md`의 4절·7절, `pyproject.toml`, `package.json`, `src/detail_page_ai/html_renderer.py`, `src/detail_page_ai/app.py`를 읽어 이미지·상태·렌더링 요구사항을 대조했다.
- `docker info`를 실행했다. 클라이언트는 응답했지만 Docker 데몬 소켓 연결에 실패했다(종료 코드 1: `failed to connect to the docker API ... docker.sock ... no such file or directory`).
- 데몬을 임의로 시작하지 않았으며 `docker build`는 실행하지 않았다. 따라서 최종 이미지 크기는 **빌드 미검증**이다.
- 예상 크기는 측정값이 아니다. AWS 배포 문서의 추정치인 약 1.5~2GB를 근거로 기록하며, `python:3.13-slim`·Node/npm·Python 런타임 의존성·Playwright Chromium과 시스템 라이브러리가 주요 구성이다.
- Dockerfile 필수 지시문과 `.dockerignore` 필수 제외 목록을 `rg`로 확인했고 모두 검출됐다(각 종료 코드 0). 문서/설정 diff 공백 검사는 오류 없이 종료됐다.

### 미해결 이슈

- Docker 데몬이 실행되지 않아 실제 이미지 빌드, Chromium 설치 성공, 최종 이미지 크기, 컨테이너 기동 및 HEALTHCHECK 통과 여부는 아직 검증하지 못했다.
- 애플리케이션에는 전용 `/health` endpoint가 없으며, 현재 이미 존재하는 legacy job 조회 경로의 404를 프로세스·포트 확인용으로 사용했다. 별도 health 계약이 필요하면 endpoint 신설이 후속 작업이다.
- 모델 추론 서버 컨테이너는 CUDA 재포팅 결과가 확정되지 않아 이번 범위에 포함하지 않았다.
