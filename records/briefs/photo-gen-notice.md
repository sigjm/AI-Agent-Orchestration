# 수정 — 사진 생성이 실패하면 판매자가 알 수 있게 한다

## 관리자 지시
"product_generated 기대치와 실제가 다르면 산출물에 표시 — 이 부분은 **판매자가 직접 확인할 수 있게끔** 해"

## 배경 (2026-09-18 실측)
부채 세트 상세페이지를 실제로 돌렸을 때 **생성 컷이 0장**이었는데 **아무 흔적도 남지 않았습니다.** 이미지 모델이 로드돼 있지 않아 FLUX 호출이 **HTTP 503** 이었는데, 코드가 예외를 조용히 삼켜 페이지는 정상으로 보였습니다.

```python
except (RuntimeError, ValueError, OSError):
    return None
```

`src/detail_page_ai/source_photos.py` 의 **988, 1033, 1330행** 세 곳입니다. 로그도 경고도 없습니다. 운영에서 이미지 서버가 죽어도 아무도 모릅니다.

## 할 것

### 1. 삼키지 말고 기록한다
세 곳의 `except` 에서 **경고 로그를 남기고**(어느 역할의 생성이 왜 실패했는지) 실패 사실을 **수집**하세요. 반환값이 `None` 인 것은 그대로 둬도 됩니다 — 파이프라인이 죽으면 안 됩니다.

예외를 더 넓게 잡지는 마세요. 지금 잡는 종류를 유지합니다.

### 2. 실패를 산출물까지 전달한다
`ProductPhotoSet` 에 실패 목록을 담을 필드를 더하고, 파이프라인이 그것을 **판매자가 보는 초안·결과 DTO까지** 전달하게 하세요.

담을 내용은 **사실만**입니다.
- 어떤 역할(`photo_id`)의 생성이 실패했는지
- 짧은 사유 (예: 이미지 모델 응답 실패)

**추측하지 마세요.** 원인을 정확히 모르면 "생성하지 못했습니다" 수준으로 충분합니다. 없는 원인을 만들어 붙이지 마세요.

### 3. 판매자가 볼 수 있어야 한다
이 정보가 **FE 초안 편집 화면까지 도달**해야 합니다. FE 구현은 우리 범위가 아니므로, **우리가 하는 일은 계약에 실어 보내는 것**입니다.
- 초안 응답(판매자가 보는 화면의 근거)에 포함되어야 합니다
- 최종 결과에도 포함되어야 합니다
- **선택(optional) 필드로 추가**하세요. BE 가 이미 우리 계약에 맞춰 구현을 끝냈으므로 **필수 필드를 늘리면 BE 가 깨집니다**
- 실패가 없으면 빈 목록이거나 생략되게 하세요

### 4. 하지 말 것
- **이미지 위에 표시를 그려 넣지 마세요.** 화면상 '참고용' 표시는 관리자 결정으로 제거된 항목입니다. 이번 것은 **메타데이터**로 전달하는 것입니다
- `asset_mode`·`fidelity_status`·`product_generated` 의 기존 의미를 바꾸지 마세요
- 실패했다고 파이프라인을 중단하지 마세요. 지금처럼 원본 기반 사진으로 채우고 **사실만 덧붙입니다**

## 테스트
- 생성기가 예외를 던지면 → 결과에 실패 항목이 담기고 경고가 남는다
- 생성기가 정상이면 → 실패 목록이 비어 있다
- 실패해도 세트 구성과 기존 사진들의 `asset_mode`·`fidelity_status` 는 그대로다
- 새 필드가 **선택**이라 기존 payload 검증이 깨지지 않는다

기존 테스트를 통과시키려고 지우거나 완화하지 마세요.
