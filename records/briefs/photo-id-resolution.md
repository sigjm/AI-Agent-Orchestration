# 수정 — 존재하지 않는 photo_id 처리와 미사용 생성 컷 노출

## 배경 (2026-09-18 부채 세트 실측)
생성 컷 5장(`lifestyle`, `detail-02`~`05`)이 **정상 생성**됐는데 **페이지에 한 장도 안 실렸습니다.**

```
page_plan 이 요구한 photo_id : hero, wide, detail
실제 사진 photo_id           : hero, packshot, detail, lifestyle, detail-02~05
```

두 가지 문제가 확인됐습니다.

1. **`wide_image` 블록이 `photo_id="wide"` 를 지정했는데 그런 사진이 없습니다.** 모델이 직접 지정한 값이라 `_DEFAULT_PHOTO_BY_BLOCK` 의 기본값(`wide_image → hero`)이 무시됐고, **조용히 `hero` 원본이 다시 들어갔습니다.** 아무 경고도 없습니다.
2. 생성 컷을 쓰는 블록(`usage_scene`)이 이번 `page_plan` 에 없었고, `detail-02`~`05` 는 **어떤 블록 매핑에도 없습니다**(`_DEFAULT_PHOTO_BY_BLOCK` 참고). 만들어 놓고 쓰이지 않았습니다.

## 담당 파일
- `src/detail_page_ai/react_document_builder.py`
- `src/detail_page_ai/pipeline.py`, `dto.py`, `models.py` (2번 전달용)
- `tests/`

## 1) 존재하지 않는 photo_id 를 조용히 넘기지 않는다 — 우선순위 높음

`_photo_ids()`(`react_document_builder.py:210`)가 블록이 요구한 id 를 **실제 사진 집합과 대조**하게 하세요.

- 요구한 id 가 사진 집합에 **있으면** 그대로 사용
- **없으면** 그 블록 타입의 기본값(`_DEFAULT_PHOTO_BY_BLOCK`)으로 대체
- 기본값마저 사진 집합에 없으면 **이미지 노드를 넣지 않는다.** 엉뚱한 사진을 끼워 넣는 것보다 비우는 편이 낫습니다
- 어느 경우든 **경고 로그**를 남기세요 (어느 블록이 어떤 id 를 요구했고 어떻게 처리했는지)

**주의**: 지금 동작에서 `wide` → `hero` 가 된 것은 우연이 아니라 다른 경로일 수 있습니다. 코드를 읽고 실제로 무엇이 일어나는지 확인한 뒤 고치세요. 추측으로 바꾸지 마세요.

## 2) 만들었지만 페이지에 쓰이지 않은 생성 컷을 판매자가 알 수 있게

**레이아웃이나 블록 선택 로직을 바꾸지 마세요.** 그건 제품 결정이라 이번 범위가 아닙니다. 지금 할 일은 **사실을 드러내는 것**입니다.

- 최종 산출물에서 **생성됐지만 `react_document` 가 참조하지 않은 사진**을 찾아 목록으로 남기세요
- 앞서 추가한 `photo_generation_failures` 와는 **다른 항목**입니다. 이건 생성에 성공했지만 미사용인 경우입니다
- 초안·결과 DTO에 **선택 필드**로 싣습니다. BE 가 이미 우리 계약에 맞췄으므로 필수 필드를 늘리면 안 됩니다
- 사실만 적습니다: 어떤 `photo_id` 가 미사용인지. 원인을 추측하지 마세요

## 테스트
- 블록이 사진 집합에 없는 id 를 지정하면 → 기본값으로 대체되고 경고가 남는다
- 기본값도 없으면 → 이미지 노드가 생기지 않는다 (엉뚱한 사진이 들어가지 않는다)
- 생성 사진이 `react_document` 에 참조되지 않으면 → 미사용 목록에 담긴다
- 전부 참조되면 → 미사용 목록이 비어 있다
- 새 필드가 선택이라 기존 payload 검증이 깨지지 않는다

기존 테스트를 통과시키려고 지우거나 완화하지 마세요.
