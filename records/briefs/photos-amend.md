# 사양 변경 — 진행 중인 "제공 사진 우선 배정" 작업에 추가 지시

관리자 지시가 한 단계 더 나왔습니다. **작업 중이라면 아래로 사양을 바꿔서 진행하세요.**

> "4장 이상이면 제공 사진 뿐만이 아니라 필요한 사진은 생성해서 제공하는 형태로"

## 바뀐 점

앞 브리프는 "제공 사진이 역할 수 이상이면 생성 없이 지금과 동일" 이었습니다. **이 조건을 없앱니다.**

`source_photos.py:714` 의 조기 반환

```python
if len(source_images) >= max(self.source_photo_variation_threshold, len(roles)):
    return self._validated_source_set(source_images, roles)
```

**이 분기를 제거하고, 사진 장수와 무관하게 항상 같은 경로를 타게 합니다.**

## 확정 사양

1. **제공된 사진이 항상 먼저다.** `roles` 앞에서부터 제공 사진을 순서대로 배정한다(`_source_original` 의미, 역할별 라벨, `hero` 는 `_source_hero` 계약 유지 — `source_original`/`VERIFIED`/원본 픽셀 보존).
2. **제공 사진으로 채우지 못한 역할만 생성한다.** 참조 이미지는 첫 장.
3. **보조 생성 컷은 장수와 무관하게 붙인다.** 활용 장면(`_generated_usage_scene`)과 디테일 뷰(`_generated_detail_view`)는 지금 생성 경로에 있는 조건 그대로 유지한다. 즉 사진을 4장 이상 받아도 상세페이지에 필요한 생성 컷은 나온다.
4. **제공된 사진은 한 장도 버리지 않는다.** 역할 수를 넘는 사진은 지금처럼 `alternate` 로 전부 보존한다.
5. 생성 자산은 `product_generated=True`, 제공 사진 기반은 `False`. `asset_mode`·`fidelity_status` 값 집합과 의미는 그대로.

## `SOURCE_PHOTO_VARIATION_THRESHOLD`
이 설정이 더 이상 조기 반환을 가르지 않게 됩니다. **설정을 삭제하지 마세요.** 남은 쓰임이 있으면 그대로 두고, 아무 데서도 쓰이지 않게 됐다면 **고치지 말고 결과 보고에 "미사용이 됐다"고만 적으세요.** 처리 방향은 관리자가 정합니다.

## 테스트 (앞 브리프의 4번을 대체)

- **사진 4장 이상: 제공 사진 4장이 모두 쓰이면서 생성 자산도 함께 나온다** (앞 브리프의 "생성 자산 0개" 테스트는 이 사양과 반대이므로 넣지 마세요. 이미 추가했다면 이 사양에 맞게 고치세요)
