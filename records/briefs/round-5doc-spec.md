# 차수별 5종 산출물 문서 규격

## 목적
레이아웃 다양화 1~9차 테스트를 **차수마다 5종 산출물 문서 형태의 로그**로 남긴다.
보고서가 아니라 기록이다. 그 차수에 실제로 일어난 일과 실제로 측정된 수치만 쓴다.

## 디렉터리 구조
기존 `docs/deliverables/experiments/round-0N.md` (단일 파일)을 **삭제**하고
아래 디렉터리로 대체한다. N 은 01~09.

```
docs/deliverables/experiments/round-0N/
  01-implementation-checkpoint.md
  02-error-analysis.md
  03-experiment-report.md
  04-inference-api.md
  05-be-fe-interface.md
```

기존 `round-0N.md` 의 내용은 버리지 말고 아래 5종으로 배분한다.

## 공통 규칙

1. **로그 형식.** 각 문서는 아래 로그 헤더로 시작한다.

```markdown
# Round 0N · <문서명> — <그 차수 한 줄 제목>

| 항목 | 값 |
| --- | --- |
| 차수 | 0N |
| 파일럿 디렉터리 | `generated/evaluation/pilot-YYYYMMDD-HHMMSS` |
| 직전 차수 기준 | `generated/evaluation/pilot-...` (1차는 baseline 명시) |
| 이미지 재생성 | 예 / 아니오 (6차 이미지 재사용 등 사유) |
| 기록 시각 | 2026-09-10 |
```

2. **자체 완결.** 그 차수 문서만 읽어도 이해돼야 한다. 다른 차수를 참조할 때는
   "Round 04에서 79.8%였다"처럼 수치를 같이 적는다. 링크만 남기지 않는다.

3. **없는 것은 없다고 쓴다.** 그 차수에 해당 영역 변경이 없으면 문서를 비우지 말고
   `## 변경 없음` 절에 "이 차수는 <영역>을 건드리지 않았다. 직전 차수 계약을 그대로
   유지한다."라고 한 문단 쓰고, 유지된 계약의 핵심을 3~5줄로 요약한다.
   **추측으로 채우지 말 것.** 근거 없는 수치·파일명·효과 주장은 금지다.

4. **과거형 기록.** 권고·향후 계획은 쓰지 않는다. "남은 한계"는 사실로만 적는다.

5. 파일 경로는 백틱, 수치는 실제 측정값. 파일럿 디렉터리·스크립트 출력이 근거다.

## 문서별 내용

### 01-implementation-checkpoint.md — 그 차수 구현 체크포인트
- 그 차수에서 바꾼 파일과 함수/상수 단위 변경 내용
- 각 변경의 코드상 위치 (`파일:심볼` 또는 `파일:줄`)
- 그 차수 종료 시점의 테스트 통과 수 (알 수 있는 경우)
- 새로 추가된 스크립트·카탈로그·CSS 등 산출물 목록

### 02-error-analysis.md — 그 차수 에러 분석
- 그 차수에서 발생한 실패·오판정·잘못된 진단을 사건별로:
  **증상 / 증거 / 원인 / 조치 / 재발 방지** 5절
- 오케스트레이션 실수(브리프 오류, 파일 충돌, 판정 기준 오설정)도 에러로 기록한다
- 그 차수에 신규 에러가 없으면 그렇게 쓰고, 이월 중인 미해결 결함을 나열한다

### 03-experiment-report.md — 그 차수 실험 (가설·결과)
- 문제 → 가설 → 실험 설계(무엇을 바꿔 무엇을 고정했는지) → 실행 명령 →
  측정 수치 → 판정 → 가설이 입증됐는지 반증됐는지 → 남은 한계
- 측정 수치는 표로: 평균 집합 일치도, 유효 공통 블록 종수, 완전 일치 쌍,
  고유 시퀀스 수, 길이 분포, 컷아웃 게이트 결과, 소요 시간
- 판정 기준을 그 차수 시점 기준으로 명시 (8차에서 기준 자체가 바뀐 점 포함)

### 04-inference-api.md — 그 차수 추론 API 영향
- 모델 호출 계약 변화: 프롬프트 구성, 시스템/유저 메시지 구조, 이미지 클라이언트
  파라미터(`steps`, `mode`, 엔드포인트), provider 설정
- 호출 횟수·소요 시간에 미친 영향
- 변경 없으면 공통 규칙 3번에 따라 처리

### 05-be-fe-interface.md — 그 차수 BE/FE 인터페이스 영향
- `page_plan` 블록 어휘, `PageBlockVariant`, `react_document` 스키마,
  `layout_id` 등 BE·FE가 소비하는 계약의 변화
- 하위 호환 여부 (기존 소비자가 깨지는지)
- 변경 없으면 공통 규칙 3번에 따라 처리

## 색인 복구
`docs/deliverables/03-second-experiment-report.md` 를 **전체 색인 겸 요약**으로 복구한다.
- 9차수 한 줄 요약 표 (차수 / 바꾼 것 / 파일럿 디렉터리 / 평균 일치도 / 판정)
- 각 차수 5종 문서로의 링크
- 전체 결론: 근본 원인 3중 구조(카탈로그 상한, 기준 오설정, 원형 선택 추첨)와
  최종 9차 판정 (52.3% / 유효 공통 0종 / 완전 일치 0쌍 / 컷아웃 6/6 OK)

## 금지
- 사람 검수 점수는 존재하지 않는다. 지어내지 말 것.
- '참고용' 라벨 누락은 **결정에 의해 미수정**으로 기록만 한다. 고치지 말 것.
- FE 렌더러 구현·프런트 통합 작업은 우리 팀 범위가 아니다. 계약 기술만 한다.
