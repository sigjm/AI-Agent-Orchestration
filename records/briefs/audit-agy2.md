# 검수 작업 — 5종 산출물과 차수 기록 검수

당신은 검수자입니다. **파일을 절대 수정하지 마세요.** 차수 기록과 평가 기록은 **시점 기록**이라 내용이 틀렸더라도 고치지 않는다. 발견만 보고합니다.

## 이 프로젝트의 기록 규칙 (검수 기준)
- 개선/실험은 **차수별로 분리**해 5종 문서로 남긴다: 01 구현 체크포인트 / 02 에러 분석 / 03 실험 보고서 / 04 추론 API 구성 / 05 BE·FE 통합 인터페이스.
- 각 문서는 **로그**다. 과거형 사실 기록이며 **권고·향후 계획을 넣지 않는다.**
- 각 문서는 차수·파일럿 디렉터리·이미지 재생성 여부·기록 시각을 담은 **로그 헤더**로 시작한다.
- 해당 차수에 그 영역 변경이 없으면 "변경 없음"이라고 명시하고 유지된 계약을 요약한다. 추측으로 채우지 않는다.
- 각 문서는 그 차수만 읽어도 이해되도록 **자체 완결**로 쓴다. 다른 차수를 참조할 때는 링크만 남기지 말고 수치를 함께 적는다.

## 확인 항목
1. round-01 ~ round-12 각 디렉터리에 **5개 문서가 모두 존재**하는가. 누락 목록.
2. 각 문서에 **로그 헤더 4요소**(차수 / 파일럿 디렉터리 / 이미지 재생성 여부 / 기록 시각)가 있는가. 빠진 것 목록.
3. **권고·향후 계획 문장**이 들어간 로그 문서. ("~해야 한다", "다음 차수에서는 ~할 예정" 같은 문장)
4. `docs/deliverables/03-second-experiment-report.md` 색인이 **12개 차수를 모두** 담고 있는가. 색인에 적힌 각 차수 수치가 그 차수 문서의 수치와 **같은 값**인가. 다르면 두 값을 나란히 적을 것.
5. **차수 간 수치 모순**: 같은 지표가 차수별 문서에서 다르게 적힌 곳. (예: 1차 라벨 준수율은 96.7 → 96.3 이다. 다른 값으로 적힌 곳이 있는지.)
6. **존재하지 않는 데이터**: 이 프로젝트에는 **사람 평가 점수도 설문 결과도 없다.** 그런 수치나 "디자이너/소비자가 ~라고 평가했다" 류의 문장이 있으면 전부 보고. `docs/evaluation/human-review-guide.md` 는 가이드 문서이므로 점수를 담고 있지 않아야 정상이다.
7. `docs/deliverables-audit.md` 의 미해결 항목 중 **실제로는 이미 해결된 것**과 **여전히 열려 있는 것**을 구분해 목록으로. 판단 근거를 파일 경로로 적을 것.

## 보고 규칙
- 근거는 반드시 `파일경로:행번호`. 행 번호 없는 지적은 채택하지 않는다.
- 추측은 `[추정]`, 파일에서 확인한 것은 `[확인]`.
- 문제 없던 항목도 "이상 없음"으로 적을 것.
- 심각도 3단계: `치명`(사실이 아닌 내용이 기록에 남음) / `불일치`(문서 간 차이) / `사소`(형식).
- 60개 문서를 전부 열어야 한다. 표본만 보고 일반화하지 말 것.
